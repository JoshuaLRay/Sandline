# U-101 — Set each character's aggression level

Epic: **Squad command**. Status, priority and dependencies live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-03: control “everyone's aggression level”; approved the
three proposed settings below in this session.

## Problem / outcome

Friendly bots share the same combat behavior. The commander needs an independent
aggression setting per character, plus a convenient apply-to-commanded-group
control. Aggression must not break the selected spread or physical separation.

## Approved behavior

- **Hold fire:** engage only through an explicit attack order. Without one,
  do not autonomously fire, suppress, throw offensive grenades or attack armour.
  Continue following, taking protective cover, healing and reviving.
- **Defensive:** return fire and stay near formation. An unprovoked visible
  enemy alone does not authorize an attack. An explicit attack order permits
  attacking its named target; otherwise do not chase a lost contact.
- **Aggressive:** engage detected enemies and advance when needed, within the
  chosen group footprint and valid navigation. Do not use unseen world state
  as knowledge or abandon the squad to chase indefinitely.

## Scope

One focused implementation PR after U-100. Add authoritative per-character
settings and touch-accessible selectors for individual bots and all commanded
bots. Respect existing commander ownership and make server state visible to all
clients, including late joiners. Human input stays under the human's control;
the stored character setting takes effect when a bot drives that character.

Proposed new-session default: Aggressive with existing engagement behavior;
new advancement is bounded by the formation/spacing rules. Preserve settings
through possession, reconnect and checkpoint retry. Explicit movement, hold,
regroup and revive orders retain precedence; attack grants permission to fight
that named target until replaced or completed. A setting change takes effect
without stale fire/throw intents. Return-fire threat recency and pursuit limits
must be validated tuning data, with shared squad threats defined explicitly.

## Acceptance criteria

- [ ] Two bots with different settings react differently to the same unprovoked
  contact; Hold fire stays silent, Defensive does not initiate, Aggressive fights.
- [ ] Defensive returns fire on a known attacker but does not pursue beyond
  formation; changing back to Hold fire clears offensive intents immediately.
- [ ] Explicit attack orders work in every setting; clearing/replacing them
  restores the selected aggression policy.
- [ ] Fire, suppression, offensive grenades, mounted/armour engagement and
  movement all obey the policy, with friendly-fire protection preserved.
- [ ] Healing, revival, protective cover and mandatory objective interaction
  still work under Hold fire and Defensive.
- [ ] Ownership, late join, reconnect, possession, retry and new-session
  defaults have Session integration coverage; mobile selectors remain usable.
- [ ] Aggressive respects selected spread and U-099 separation.

## Handoff / evidence

Implemented server-owned per-character policies and individual/group selectors
in the Squad panel. Human input stays manual; the character policy persists for
later bot control. Commands check ownership, and all clients/late joiners receive
authoritative modes. New sessions default to Aggressive; existing Session fields
retain settings through possession and checkpoint retry.

Hold fire suppresses autonomous gunfire, suppression, offensive throws,
detonation and armour selection. An explicit attack permits its named target.
Defensive only targets a visible remembered attacker threatened within the
existing validated memory.threatSeconds (4 s); nearby impacts, near misses and
detonations provide threat memory, not merely the sound of a shot. It uses
existing formation-bounded combat cover and does not pursue a lost contact.
Aggressive can advance towards a previously seen contact's remembered position,
within formationBand and reachable terrain. A shot heard without a visual
identification does not authorize this new pursuit. Non-aggressive following
still seeks protective cover when pressured, and healing/revival/order branches
retain priority. Policy changes clear stale offensive and movement intents.

`pnpm verify`: 259 files / 2769 tests passed. Added tests cover different modes
against common known contacts, named attack permission, immediate cease-fire,
known near-miss return fire, bounded visual pursuit versus heard-only contact,
commander ownership and late join. Existing attack-cover grid remains 24/24 wins
with zero bot deaths; squad/cover-duel/pinned/MG and friendly-hit checks pass.
The initial pursuit of sounds alone caused a 23/24 attack regression and was
removed before retaining this change; thresholds were not weakened.

Mission over 20 seeds: one-human completion 35%, six-human 10%; cover 36%,
suppression 3.60, all gates pass. Original main was 50% / 0%; these controls
are not a claim of mission win-rate improvement or U-087 completion.
