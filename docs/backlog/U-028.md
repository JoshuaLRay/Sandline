# U-028 — Make manual reloads server-authoritative

Epic: **Maintenance**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: found during U-006 (2026-09-27) while checking its criterion "ammo becomes available only on authoritative reload completion". Not an owner report.

## Problem / outcome

A manual reload (R) never reaches the host.
- **Client:** `CombatQA.requestReload` refills only the page's mirror of the magazine, on the local clock.
- **Server:** the protocol has no reload message. The server reloads a slot only when a Fire arrives on an empty magazine (`Session.ts`, "Auto-reload so a player who empties a magazine…"). Its snapshot comment says so: "a client's manual reload is its own picture".

A player who reloads with rounds left is shown a full magazine the host does not have. Their predicted shots, tracers and ammo counter then run ahead of the host's magazine. When the host's copy empties, its own auto-reload refuses shots the page has already drawn. Remote soldiers also see no reload body layer for a manual reload, because the replicated reload progress stays 0.

## Scope

Send the reload request to the host and run it through the same `startReload` on the slot's authoritative weapon state, with the page's prediction reconciling to it. Keep the reload's balance (seconds, magazine size) unchanged. Mind the protocol budget: the EXT/variant codes are nearly full.

## Acceptance criteria

- [x] A manual reload with rounds left refills the host's magazine on the host's reload clock. The page's count follows the host's, and cannot run ahead of it.
- [x] A shot fired during a manual reload is refused by both sides alike, with no drawn tracer the host did not fire. (One residual edge at the reload's end, below.)
- [x] Remote players see the reload (the body's reload layer and its stage sounds) for a manual reload too.
- [x] Headless integration coverage for the manual reload over a hosted room, including a reload requested mid-burst and one interrupted by a weapon switch.

### What was wrong (on `main`, b976362)

- **R never reached the host.** `CombatQA.requestReload` refilled only the page's copy of the magazine. The protocol had no reload message; the host reloaded a slot only when a Fire landed on an empty magazine.
- **The page's count was never the host's.** The snapshot did not carry the magazine, so after a manual reload the page showed rounds the host did not have, drew their tracers, and the host later refused shots the page had already drawn.
- **Nobody else saw a manual reload.** The replicated reload progress is the host's, and the host had none, so remote bodies showed no reload layer and played no stage sounds for it.
- **The host's reload finished only on the next Fire.** `finishReload` ran inside Fire handling, so a finished reload was never reported as a full magazine until the player fired again.

### Change

- **On the wire** (protocol 37):
  - A `Reload` message. MISSION_VARIANT and EXT are full, so it rides the Equip message's reserved item code 7 (`RELOAD_ITEM`), which no loadout item reaches. A test pins that.
  - The snapshot's Weapon component gains `ammo` (7 bits, `AMMO_BITS`), appended after U-024's pouch counts (ADR-009). A test holds every weapon's `magSize` to what 7 bits carry.
- **On the host:**
  - `applyReload` runs the request through the same `finishReload`/`startReload` on the slot's own weapon state and clock. Reload seconds and magazine size are unchanged.
  - It refuses the request, as it must refuse a forged one, when the player is down or dead, on a mounted gun, or holding a grenade or rocket. `startReload` itself refuses a full magazine or one that is already reloading.
  - Each step finishes every seated human's reload on its clock, so the snapshot, and the next shot, see the full magazine without a Fire to settle it.
  - The existing Equip path already cancels a reload on a switch.
- **In the page:**
  - `NetClient.reload()` sends the request reliably. `main.ts` sends it on the tick any reload begins on the page, whether from the key or an empty magazine reloading itself.
  - `NetClient.magazine` is our own soldier's weapon and rounds from our snapshot, or from `Possessed` until the next snapshot.
  - Every tick `CombatQA.reconcileMagazine` follows the host's count, on the same pattern as U-024's pouch:
    - Each shot of ours is spent at once and held pending until the host's count drops for it. A shot the host never takes lapses after `MAGAZINE_HOLD_SECONDS` (1.5 s).
    - While our reload runs, and after it until the host's lands (its count rises) or the hold passes, our full magazine stands.
    - Otherwise the count is the host's less what is pending. It is never more than the host has.
    - Nothing changes while the host is on another gun (a switch in flight) or on a mounted gun.
  - The page still refuses its own shots while it reloads (`tryFire`), so no tracer is drawn for a shot fired mid-reload.

### Residual edge (not fixed, by design)

The page's reload starts and ends one link latency before the host's, the same offset its Fire messages carry, so on a steady link a shot fired the tick the page's reload ends reaches the host just as the host's ends.

Link jitter can bring that Fire in a tick early. The host then refuses it, the page's pending shot lapses, and its count returns to the host's. The only visible cost is that one drawn tracer. This is the same edge the pre-existing empty-magazine auto-reload and fire-rate cadence already had. Closing it would take a shot grace on the host's reload, which is a balance change this card rules out.
