# U-051 — A joining player may take any free slot

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-021](U-021.md) follow-up, owner decisions 2026-09-29 (D-8 in the roster doc).

## Problem / outcome

Owner decision (2026-09-29, D-8): a joining player may take any free slot, not only the lowest. Today a join takes the lowest free (bot) slot, and U-026 can only switch into a bot after joining.

## Scope

A slot chosen at join (in the room lobby, showing each free slot's character), honoured by the host when it is free and otherwise falling back to the lowest free; a resume keeps its own seat. No wire change is assumed but the Join or a room command may need one (then a protocol bump). Once seated, U-026's switching is unchanged.

## Start here

`packages/server/src/session/Session.ts` (the join and seating path), `packages/client/src/ui/RoomLobby.ts`, `packages/shared/src/net/protocol.ts`.

## Acceptance criteria

- [x] The join screen lists the six characters and lets a joining player pick one; the host seats them there if it is free, and otherwise (taken, or a bot with a dropped player's claim on it) in the lowest free slot. (Proposal: the choice is on the join screen, before the roster is known, so a taken slot is not greyed out; it falls back. Once in the room, U-026's switching still moves into any bot.)
- [x] Two players choosing the same slot at once: one gets it, the other the lowest free, with no duplicate character.
- [x] A resume returns to the player's own seat.

## Verification

Shared and server tests, then `pnpm verify` and the CI jobs.

## Handoff / evidence

Implemented on `task/U-051-choose-slot`; awaiting review. No owner verdict is claimed.

**What changed.** `Join` gains an optional `slot` (0-5; 3 bits, 0 = none; protocol 49). The host seats a resume in its own slot first, then the asked-for slot if a bot holds it with no claim on it, then the lowest free one (`Session.wantedSlot`). The join screen (`Lobby.ts`) has a "Character" field (any free, or the six by name); the page sends it on the first join only, a rejoin uses its resume token.

**Evidence.** `packages/client/src/weapons/joinSlot.test.ts` (asked slot honoured with its character; no ask takes the lowest; two asking the same slot get one each and no character is doubled; an out-of-range ask falls back; a resume returns to its own seat whatever is asked) and `protocol.test.ts` round trips.
