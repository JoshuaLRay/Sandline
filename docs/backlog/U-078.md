# U-078 — In-mission menu: restart from checkpoint, restart mission, return to mission select

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: owner decisions on the campaign design, 2026-10-01 ([design doc](../design/CAMPAIGN.md)).

## Problem / outcome

The owner wants three choices when stuck or done: restart from the last checkpoint, restart the mission, or return to mission select. Today a failed mission offers only retry (checkpoint) or restart.

## Scope

Add the third choice and one menu that offers all three at any time the leader pauses and at the end of a mission (complete or failed). *Return to mission select* ends the run without completing it and goes to U-072's select screen; progress already saved at checkpoints is kept for a retry of that run but is not a completion.

## Start here

`Session.requestRestart`/`retryMission`/`restartMission`, the pause and after-action UI (`client/src/ui/scoreboard.ts`), U-072.

## Acceptance criteria

- [ ] The menu offers the three choices to the team leader (design doc Q2).
- [ ] Each does what it says; leaving does not mark the mission complete.
- [ ] The choices are covered by session tests.

## Handoff / evidence

Not started. Scope recorded only; nothing is claimed.
