# U-078 — In-mission menu: restart from checkpoint, restart mission, return to mission select

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: owner decisions on the campaign design, 2026-10-01 ([design doc](../design/CAMPAIGN.md)).

## Problem / outcome

The owner wants three choices when stuck or done: restart from the last checkpoint, restart the mission, or return to mission select. Today a failed mission offers only retry (checkpoint) or restart.

## Scope

Add the third choice and one menu that offers all three at any time the leader pauses and at the end of a mission (complete or failed). *Return to mission select* ends the run without completing it and goes to U-072's select screen; progress already saved at checkpoints is kept for a retry of that run but is not a completion.

## Start here

`Session.requestRestart`/`retryMission`/`restartMission`, the pause and after-action UI (`client/src/ui/scoreboard.ts`), U-072.

## Acceptance criteria

- [x] The menu offers the three choices to the room's host, the team leader (design doc Q2, decided 2026-10-01).
- [x] Each does what it says; leaving does not mark the mission complete.
- [x] The choices are covered by session tests.

## Handoff / evidence

Implemented, in REVIEW (the PR is the evidence).

- Protocol 63: `RunOffer.result` gains `progress` (2 bits), so the host holds the way out while the mission is on; `runOffer()` is made at the start, on a retry (new attempt), to joiners and when the host changes. A round-trip test covers it.
- Server: a mid-mission `MissionRestart` (checkpoint, or `full` from the start) is honoured from the room's host, in a room with a campaign file; after a mission it is as before (any human). A `choose` of another mission while the mission is on is the same handoff as after one; the same mission and kind is ignored. `completedMissions` is untouched by leaving (`runChoice.test.ts`, 6 new tests).
- The checkpoint of the run left is **kept**, tagged with its kind (`CampaignCheckpoint.run`), and resumed only by a run of that kind of that mission; any other checkpoint in the file is carried through untouched until the run makes its own. One checkpoint is held at a time, so leaving mission B mid-way after leaving A replaces A's if B reached one.
- Client: the pause menu has the host's mission section (restart from the last checkpoint, restart the mission, return to mission select with each option's briefing), from `missionMenuModel` (`runChoice.test.ts`, 4 new). Non-hosts and rooms without a campaign see nothing new. After a mission the after-action panel of U-090 is the end-of-mission menu (retry or restart there too).
- Not claimed: an owner playtest of the menu, or a two-browser run of leaving mid-mission.
