# U-099 — Characters cannot occupy the same space

Epic: **Squad command**. Status, priority and dependencies live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-03: “Do not allow characters to occupy the same space.”

## Problem / outcome

Characters must remain physically separated, independently of squad spread or
aggression. No reproduction or screenshot was supplied. Code inspection shows
that local avoidance returns steering velocities; it is not a final collision
constraint. `Session.driveBots` only applies steering to bodies with movement
inputs. This is a hypothesis for overlap, not a reproduced cause.

## Scope

One focused implementation PR: enforce non-overlapping character bodies while
preserving world collision, authoritative movement and client reconciliation.
Cover friendly bots, humans, enemies and escorted characters. Test occupied
destinations, stationary bodies, simultaneous approaches and exactly coincident
positions. Include downed/prone bodies in the collision policy; explicitly
document corpse handling rather than accidentally inheriting steering's omission
of dead bodies. Never resolve an overlap by pushing a character into a wall,
off a ledge or onto a different floor.

Use the existing movement/hitbox dimensions as the source of physical size.
Deterministic priority must avoid oscillation and starvation in narrow passages.
When a destination has no room, wait or choose a valid distinct position.
Avoidance may still steer before collision resolution; spread controls must not
lower the physical minimum. No new command UI in this task.

## Acceptance criteria

- [ ] Reproduce and record overlap in a real Session before changing behavior.
- [ ] Character bodies remain distinct when stationary, moving toward one
  destination, approaching head-on, or initialized at identical coordinates.
- [ ] Human/bot, bot/bot, enemy and escort interactions obey the same documented
  physical rule; downed, prone and corpse cases are explicit and tested.
- [ ] Narrow passages, walls, rubble, vaulting, different floors, respawn and
  checkpoint restoration do not create tunnelling, invalid ground or deadlock.
- [ ] Multiplayer prediction converges without sustained correction jitter.
- [ ] Existing squad combat and navigation gates remain green.

## Verification

Meaningful Session integration tests, navigation/formation regressions and
`pnpm verify`. Run `squad`, `cover-duel`, `pinned` and `mg` with zero friendly
hits; measure both mission budgets over 20 seeds before retaining a gameplay
change. Record a manual two-player bottleneck check as pending until performed.

## Handoff / evidence

Implemented shared circular character footprints (0.35 m radius from movement
configuration), authoritative constraints for humans, bots, enemies and escorts,
and the same constraint during browser/headless prediction and replay. Downed,
prone and dead bodies occupy a shorter footprint until the existing removal path
removes them; different floors are separated by vertical intervals. Static world
collision and support height constrain relocation. Group orders reserve distinct
points, behind an escort's arrival area where needed.

Reproduction: six idle Session characters at identical coordinates remain
coincident with the ordinary controller; the new Session test separates them.
A live opposing six-bot doorway fixture checks every tick and every arrival.
Shared tests cover stationary contact, sliding, exact coincidence beside a wall,
lying bodies, different floors and prediction. Existing checkpoints, vaulting,
revival, escort and navigation checks remain green. The transport matrix isolates
transport by starting wandering clients apart; physical contact is covered by
the new constraint/prediction and Session tests, not a zero-correction promise
for delayed remote snapshots.

`pnpm verify`: 257 files / 2762 tests passed, including squad, cover-duel,
pinned and MG gates. Mission over 20 seeds: one-human completion 35%, six-human
10%; cover 36%, suppression 3.53; all existing floors pass. Unchanged main was
50% / 0% over the same seeds. The one-human result fell 15 percentage points;
this is a physical-rule change, not a claim of improved mission tactics.

Pending: manual two-human bottleneck/jitter and owner gameplay review. An
initially impossible fully packed location cannot promise instant separation;
the resolver tries valid nearby positions or waits without crossing walls.
