# U-039 — Never show the crosshair on mobile

Epic: Mobile. Status, priority, dependencies and branch/PR live in BACKLOG.md.
Source: 2026-09-29, owner playtest feedback on a phone: "Changing to landscape on mobile makes the game think I am on desktop. This should not be the case. The zoom out cam should be up to 6x (double what it is now) when in portrait mode on mobile. 3x (as now) for landscape mode on mobile. Mobile players should never see cross hairs."

## Problem / outcome

Observed: a crosshair is visible on mobile (which state/orientation: UNKNOWN; possibly only after the landscape desktop misdetection, see U-037). Expected: mobile players never see it.

## Scope

One PR: hide `#crosshair` for mobile in every state (ADS, spectating, orientation). Keep the aim raycast and desktop crosshair behaviour intact.

## Start here

`#crosshair` in `packages/client/index.html`, `ui/qa.css`, and the class toggles near `main.ts:2662` and `2897`. Confirm it is not tied to the mobile-mode misdetection before choosing the fix.

## Acceptance criteria

- [ ] No crosshair element is visible on a touch device in any orientation or state.
- [ ] Desktop crosshair, ADS and colour-coding unchanged.

## Verification

`pnpm verify`; emulated-touch screenshot in both orientations.

## Handoff / evidence

Branch `task/U-039-mobile-no-crosshair`.
- Cause (from code): `#crosshair` was hidden only by `@media (max-width: 640px)`, so a phone in landscape (wider than 640px) showed it. The HUD also toggles `.hidden`/`.sighted`, which never forced it on for mobile.
- Fix: `html.mobile #crosshair { display: none !important }` in `ui/qa.css` (the `html.mobile` class comes from U-037). The aim raycast in `main.ts` is untouched; desktop rules are unchanged.
- Test: `ui/mobileCrosshair.test.ts` asserts the rule exists (a CSS-text check, not a rendered screenshot).
- Pending: owner check on a phone in both orientations, including ADS and spectating.
