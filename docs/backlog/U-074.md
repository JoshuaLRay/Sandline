# U-074 — Objectives in any order: parallel objectives and optional enemies

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: owner decisions on the campaign design, 2026-10-01 ([design doc](../design/CAMPAIGN.md)).

## Problem / outcome

A mission's objectives are a strict sequence today (`MissionRun` has one current objective, and each completion is a checkpoint). The owner wants objectives that can be done in whatever order the players choose, where applicable, without clearing every enemy.

## Scope

Let a mission data file group objectives into **stages**: the objectives in a stage are all open at once and may be completed in any order; the stage is complete when every *required* one is (an objective may be marked `optional`). Each completion is still a checkpoint, and progress, the HUD line, compass markers and the briefing show every open objective. Triggers and scripts keyed to `objective-start` and `objective-complete` keep working per objective. A mission with only single-objective stages behaves exactly as mission-01 does now. Proposal: no new objective types; `rescue`, `reach`, `destroy`, `upload` and `survive` are enough. **Not in scope:** removing `clear-and-hold` (it stays valid for the old mission), the escort (U-075), or any new mission's content.

## Start here

`shared/src/sim/mission.ts` (`MissionDef`, `OBJECTIVE_TYPES`, the `Mission` wire view), the server `MissionRun`, `shared/src/sim/events.ts` (objective triggers), `client/src/ui/missionHud.ts`, the checkpoint code in `Session.ts` (`captureMissionCheckpoint`). The `Mission` message is on the wire: a protocol bump and its tests are expected.

## Acceptance criteria

- [ ] A mission file can declare a stage of several objectives; players can finish them in either order and the stage completes when the required ones are done.
- [ ] An optional objective's completion is credited but not required; a checkpoint is saved at each completion and a retry restores which were done.
- [ ] The HUD, briefing and compass show every open objective.
- [ ] A mission with only sequential single-objective stages is unchanged (mission-01's tests and `sim-run --scenario mission --seeds 3`).
- [ ] Headless coverage of both orders and of a retry mid-stage; `checkMission` validates stages.
