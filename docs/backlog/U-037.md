# U-037 — Keep mobile controls and layout when the phone is rotated

Epic: Mobile. Status, priority, dependencies and branch/PR live in BACKLOG.md.
Source: 2026-09-29, owner playtest feedback on a phone: "Changing to landscape on mobile makes the game think I am on desktop. This should not be the case. The zoom out cam should be up to 6x (double what it is now) when in portrait mode on mobile. 3x (as now) for landscape mode on mobile. Mobile players should never see cross hairs."

## Problem / outcome

Observed: rotating a phone to landscape makes the game behave as desktop.
Expected: a mobile player stays in mobile mode in both orientations. Device,
browser, build/URL and exactly which desktop behaviours appear: UNKNOWN.

## Scope

One PR: mobile detection must not depend on orientation or viewport size, and
every layout/CSS branch that decides mobile vs desktop must agree. Zoom limits
(U-038) and the crosshair (U-039) are separate cards.

## Start here

Hypotheses, not verified: `mobileMode` in `packages/client/src/main.ts` is
computed once from `?mobile` or `(pointer: coarse)`; CSS such as
`packages/client/src/ui/menu/menu.css` uses `(max-width: 600px), (pointer: coarse)`
and a landscape phone exceeds 600px wide. Also check `LocalInput.ts` and any
other viewport-width checks. Reproduce in landscape emulation first.

## Acceptance criteria

- [ ] Rotating portrait <-> landscape on a touch device keeps touch controls, mobile HUD and mobile menus.
- [ ] Mobile detection is a single shared helper used by TS and matching CSS conditions; unit-tested.
- [ ] Desktop (fine pointer) behaviour is unchanged, including narrow desktop windows.

## Verification

`pnpm verify`; emulated touch device in both orientations. A real-phone check is a human verdict: do not invent one.

## Handoff / evidence

Branch `task/U-037-mobile-orientation`, stacked on #181 (unmerged intake).
- Cause (verified by reading code): JS `mobileMode` used the coarse pointer and was orientation-stable, but the mobile layout CSS (`hud.css` 720/600px, `qa.css` 640px) was width-based, so a landscape phone got the desktop layout (squad panel, scoreboard, QA panels).
- Fix: `ui/mobileDevice.ts` (`detectMobile`, `applyMobileClass`) sets `html.mobile`; those CSS blocks now also apply under `html.mobile`. Narrow desktop windows keep their width rules.
- `pnpm verify`: all pass except one `audio` determinism test that timed out under load; it passes when run alone.
- Checked: [x] layout follows device not width (CSS by code review); [x] shared helper, unit-tested; [x] desktop rules unchanged. Pending: real-phone rotation check by owner. Crosshair stays hidden only by width (<640px), so it still shows in landscape: U-039.
