# U-142 — Profile Qalat cold-start load-time overruns

Epic: Maintenance. Status, priority, dependencies and work live in BACKLOG.md.
Source: agent observation during U-138 verification, 2026-10-07.

## Observed problem

On U-138 head `e9c23b01303cb2c8ce2222311fd6d99b4db77a06`, CI #1751's
first streaming attempt failed the existing Qalat first-playable-frame gate at
31,109 ms against the unchanged <30,000 ms limit. A local production client
build measured 32,870 ms with the same command, Node v24.19.0 and Chromium.
Client/server/shared content is identical to main `8336605`; U-138 only adds
isolated authoring tools/evidence. The same-head streaming retry passed that
gate. Final retry results and later head checks are recorded in
[PR #310](https://github.com/JoshuaLRay/Sandline/pull/310).

Reproduction: pinned pnpm, `pnpm --filter @sandline/client build`, install
Chromium, then `SANDLINE_LOAD_WORLD=qalat-road pnpm check:load-time`.
The helper applies 4 Mbit/s down, 1 Mbit/s up and 100 ms latency, selects
“Practise here” and measures the first rendered playable frame from navigation.

Observed: the existing cold-start gate has little timing margin. The cause is
unverified; download, startup/render cost and runner variation need separate
measurements. Do not attribute it to the isolated geometry or weaken the limit.

## Intake / next action

Profile a fresh main build and the existing practice-pack preload, record cold
resource/network and startup/render timings, then scope a focused fix from the
measured bottleneck. Preserve the 30 s budget and first-frame definition; do not
make the gate pass by adding automatic retries or omitting required assets.
U-138's single diagnostic retry is evidence of variation, not a performance fix.
This report claims no implementation or owner acceptance.
