# U-090 — The host chooses the next run; briefing, debrief and the handoff

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-072](U-072.md) (leaf 3 of 3), owner decisions 2026-10-01 (Q2: the host; Q3).

## Problem / outcome

After a mission, complete or failed, the **room's host** chooses what is played next: a campaign run of the newest mission reached, or a replay run of any beaten one. A room is one world for life today (a campaign code opens the world in the save), so choosing a mission means changing the save's world and run kind and bringing the room along.

## Scope

A host-only message carries the choice; the server validates it against U-088's options (a leader cannot skip ahead), writes the world and run kind into the save (U-089), and tells the room's clients to reconnect to the same code, which then builds the room on the new world. The after-action screen shows the mission's authored debrief (U-088) and, for the host, the choice with each mission's briefing; others see what the host is deciding. A failed campaign run offers a retry of the same mission or a replay. Not in scope: the in-mission menu (U-078), loadout carry-over (U-077).

## Handoff / evidence

Implemented, in REVIEW (the PR is the evidence; `pnpm verify` and the CI rows on its head).

- Protocol 62: `RunOffer` and `Handoff` events (variant field widened to 3 bits), `RoomCommand` `choose` (bool = replay, string = mission); round-trip tests in `protocol.test.ts`.
- Server: the host is the lowest-numbered seated human (`hostSlot()`); the offer goes out with the mission result, to joiners and when the host leaves. `choose` from anyone else, or beyond `runOptions` (skipping ahead), is refused. A failed campaign run of the same mission retries in place; otherwise `handOff()` saves the campaign with the new world (no checkpoint; run kind for a replay), sends `Handoff`, retires the room and closes it. `runChoice.test.ts` (11), `retire.test.ts` (2) cover choice, refusal, save, retire and a restarted host resuming.
- Client: `runChoiceModel` (pure, `runChoice.test.ts`, 5 tests) and the after-action panel on the scoreboard (debrief, one button per option with its briefing, "X is choosing" for others); `NetClient` exposes `runOffer`/`chooseRun` and `onHandoff`, on which `main.ts` rejoins the same code in the same slot instead of showing the close as a refusal.
- Not claimed: an owner playtest of the flow (host chooses, others follow), nor a real two-browser handoff run.
