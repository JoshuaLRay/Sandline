# U-020 — Add the roster’s missing weapon archetypes

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-26](2026-09-26-feedback.md), plus any legacy bug named below.

## Problem / outcome

The roster requires sniper rifles, LMG, AR, scoped AR, SMG and shotgun. A current marksman rifle must not be silently used as both the scoped AR and every sniper without the approved roster specifying it.

## Scope

Audit current weapon IDs against the approved roster and add only the missing archetypes, reusing existing models, mechanics and pipelines where appropriate. If more than one substantial new weapon behavior is required, split this card into per-archetype leaves before making it READY.

## Start here

These are entry points, not a prescribed edit list; verify current code before changing it.

- `packages/shared/src/sim/weapons.ts`
- `packages/tools/src/art/weapons`
- `packages/client/src/weapons`
- `packages/shared/src/data/audio/weaponSounds.json`

## Acceptance criteria

- [ ] Every approved roster firearm has a valid gameplay definition, model, sound mapping and ammo/reload behavior.
- [ ] Sniper and scoped-AR roles match the approved distinctions; SMG/shotgun support use works without ADS.
- [ ] Weapon tuning is schema-validated data and server-authoritative; no class-specific numeric magic constants.
- [ ] Generated assets/audio and budgets are current; individual firing/reload behavior has regression coverage.

## Verification

Run weapon tests, netcode tests for contract changes and affected generation/budget commands. Compare each firearm against the approved roster and expose it for visual/audio review.

Follow the shared [delivery workflow](../../.claude/commands/next-task.md), including `pnpm verify`. Record commands/results and observed acceptance evidence below. Visual/audio quality and owner decisions are not proven by a passing test.
