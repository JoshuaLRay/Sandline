# U-098 — The mouse comes back when the mission ends

Epic: **Controls / UI**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: owner playtest report, 2026-10-03: "Mission failure has buttons to click, but I can't get my mouse back to click — when I hit Esc, a menu overtakes it for settings etc. Make the mouse come back upon mission failure."

## Problem / outcome

Observed: when a mission ends, the scoreboard/after-action panel shows its restart and run-choice buttons, but the pointer is still locked to the canvas. Pressing Esc releases the lock but also opens the pause menu over the panel. Expected: the cursor is free as soon as the mission is over (failure or success), so the buttons can be clicked. Build/URL, mode and frequency: UNKNOWN (reported for failure; success shares the same panel).

## Scope

Client only. On the frame the mission state leaves `progress`, release the pointer lock. Do not change the pause menu, Esc handling or the click-to-relock behaviour. Hypothesis (not verified in a browser): nothing releases the lock at mission end.

## Start here

`packages/client/src/main.ts` (frame loop, `missionOver`); `packages/client/src/input/LocalInput.ts` (pointer lock, Esc).

## Acceptance criteria

- [ ] On entering a non-`progress` mission state the pointer lock is released once, and the scoreboard buttons are clickable without pressing Esc.
- [ ] A new attempt (state back to `progress`) does not leave the cursor stuck free: the next canvas click relocks as usual.
- [ ] Esc / pause behaviour unchanged.

## Verification

Unit test on the transition helper; `pnpm verify`. Manual browser confirmation by the owner is pending.
