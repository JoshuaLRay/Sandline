# U-186 — Inventory and persistence architecture (ADR)

Epic: Loot and progression ([U-183](U-183.md)). Pillar: P8.
Size: M (ADR plus a spike if needed). Human verdict: none beyond owner acceptance of any ADR that supersedes ADR-019.
Status, priority, dependencies and branch/PR live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-16 — required epic phase 3 ("Inventory and persistence architecture").

## Problem / outcome

Decide, in an ADR, how items, instances, soldier loadouts and the squad stash
are stored, synchronised and migrated: instance identity, the
single-location invariant, transactional moves, save schema and migrations
from today's numeric indices, wire messages for inventories, and limits.

## Scope

- ADR-0NN covering LOOT-PROGRESSION §13 as decided by U-185; if the session
  chose player/account progression, a separate ADR superseding ADR-019 §2.
- A short spike if needed: SQLite schema for stash and instances in
  `CampaignDatabase` with a migration test.
- Multiplayer: join, leave, switch (U-026), disconnect grace, capture (U-061),
  checkpoint retry; bots as owners of soldiers' kit.
