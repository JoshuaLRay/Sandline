# U-040 — Weapon data contract and the roster's firearm definitions

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-020](U-020.md) on 2026-09-29 (that card required splitting before READY: more than one substantial new weapon behavior, plus art, audio and wire changes).

## Problem / outcome

The roster (docs/design/squad-roster.md) needs a left-handed bolt-action sniper (slot 4), a semi-automatic sniper (slot 5), an SMG (support), a scoped AR (slot 3) and the squad LMG. Handedness and firing action must be validated, machine-readable weapon data, not presentation.

## Scope

`weapons.json` gains `action` (`auto`/`semi`/`bolt`) and `handedness` (`right`/`left`) on every row, validated (action must agree with `auto`); new rows `smg`, `carbine-scoped`, `sniper-semi`, `sniper-bolt-left`; a `canWield(def, leftHandedOnly)` eligibility check U-029 can call. The new guns reuse existing generated models and report sounds through the current mappings. **Not in scope:** the wire (U-041), new models (U-042), new sounds (U-043), giving anyone the guns (U-021/U-029).

## Start here

`packages/shared/src/sim/weapons.ts`, `packages/shared/src/data/weapons.json`, `packages/shared/src/data/audio/weaponSounds.json`, `packages/client/src/weapons/weaponModels.ts`.

## Acceptance criteria

- [x] Every weapon row declares `action` and `handedness`; a contradictory row fails to load.
- [x] Slot 4's `sniper-bolt-left` is bolt-action and left-handed; slot 5's `sniper-semi` is semi-automatic; the SMG and scoped carbine exist as full-auto rows.
- [x] Left-handed eligibility is machine-readable (`canWield`); only `sniper-bolt-left` is left-handed.
- [x] Tuning is schema-validated data; no per-character constants.
- [x] Model and sound mappings exist for each (reusing current assets, marked as borrowed).
- [x] Regression tests cover the schema, the roster rows, eligibility and the bolt-action cadence.

## Verification

`pnpm vitest run` for shared/client/server, then `pnpm verify`. Tuning numbers are first-pass placeholders for a playtest, not an owner-approved balance.
