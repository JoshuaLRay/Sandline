# U-021 — Bind six persistent characters to the squad slots

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-26](2026-09-26-feedback.md), plus any legacy bug named below.

## Problem / outcome

The current slice uses Team Leader/Marksman classes; the desired squad is six distinct characters with fixed identities and equipment/skills.

## Scope

Implement the approved roster as validated data and bind one character identity to each of the six slots. Update lobby, HUD, bots, loadouts and persistence using ADR-001’s same-entity possession model.

## Acceptance criteria

- [ ] The six required roles appear exactly once except snipers, which appear twice; names and loadouts are visible in selection/HUD.
- [ ] A joining human possesses the existing character; leave/reconnect preserves the slot identity and valid state.
- [ ] Campaign progress and older saves have an explicit compatible migration/default path; no silent loss of existing progress.
- [ ] Required leader/order permissions and bot loadouts continue to function, and duplicate character selection is impossible.
