# U-021 — Bind six persistent characters to the squad slots

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-26](2026-09-26-feedback.md), plus any legacy bug named below.

## Problem / outcome

The current slice uses Team Leader/Marksman classes; the desired squad is six distinct characters with fixed identities and equipment. Skills are deferred by the owner (2026-09-29) and are not part of this card.

## Scope

Implement the approved roster as validated data and bind one character identity to each of the six slots. Update lobby, HUD, bots, loadouts and persistence using ADR-001’s same-entity possession model.

## Start here

These are entry points, not a prescribed edit list; verify current code before changing it.

- `docs/adr/019-persistence.md`

## Acceptance criteria

- [x] The six required roles appear exactly once except snipers, which appear twice; names and loadouts are visible in selection/HUD.
- [x] A joining human possesses the existing character; leave/reconnect preserves the slot identity and valid state.
- [x] Campaign progress and older saves have an explicit compatible migration/default path; no silent loss of existing progress.
- [x] The support (slot 2) is third-person only: first-person view is unavailable to it by every path (saved preference, respawn, reconnect, possession change), and it has no ADS and no pistol.
- [x] Required leader/order permissions and bot loadouts continue to function, and duplicate character selection is impossible.

## Verification

## Handoff / evidence

Branch `task/U-021-bind-characters`.
- **Data (`classes.json`, `classes.ts`):** the file keeps its name and `classId` on the wire and in saves (so no protocol change), but each entry is now one of the six characters, bound to its slot by `slotDefaults` (unique, validated). New per-character flags `ads` and `firstPerson` (default true). `assignClasses()` is just the slot table; `required` and human picks are gone. Loadouts: Preach carbine + pistol; Brennan LMG + pistol; Holloway (support) SMG + shotgun, no pistol, no sight, no first person; Ortiz scoped carbine + pistol; Marsh left-handed bolt sniper + pistol; Vance semi-auto sniper + pistol. Health, pouches and order scopes are proposals except where the owner decided (Preach leads, the support's kit, Brennan's rocket launcher, no skills); order scopes deliberately keep what each slot had before (slots 0-2 reach the squad, 3-5 their fireteam) so the commander model of U-025 works unchanged.
- **Server (`Session.ts`):** a slot's character is set once and never changes, so join, leave, drop and resume keep it and a held seat keeps its pouch (the pick/held-seat machinery was removed). The `class` room command from an old page is ignored, so a duplicate is impossible. `mayAim` takes the sight from the support's shots whatever its page sends.
- **Two guards U-018 needed once these guns exist (U-029 keeps the full exchange rules):** a gun swapped out for a pickup now always goes to the ground (before, only carbines, marksmen and breachers did, so a swapped-out LMG or sniper would have vanished), and a soldier whose primary is left-handed takes no gun off the ground (the owner's rule for the slot-4 sniper).
- **Client:** the lobby's class picker is gone and rows show the character; HUD and command rows show the three-letter code (PRC, BRN, HOL, ORT, MAR, VAN); the briefing lists the squad by name; key 2 is the secondary (the pistol, or the support's shotgun); `restrictView` (viewState, applied every frame from the seated character) keeps the support in third person with the sight down on every path (respawn, reconnect, possession). The key legend in settings is updated to the U-045 keys.
- **Saves:** `classId` in a save is only a label. An older save with `team-leader`/`marksman` loads, each slot keeps its rank and XP, and the next save writes the character ids (tested). No schema change.
- **Tests:** rewrote the classes tests (shared and server); new tests for the fixed table, unique defaults, the support's restrictions on the host and the page, the left-handed pickup rule, the older save, and the view restriction. Updated the HUD, command, briefing and pickup tests for the roster. `pnpm verify` passes; `pnpm sim-run --scenario mission` passes. `--all-missions` reports 0 of 6 runs completing, identically on `main` before this change, so it is not from this task.
- **Not done here (recorded as cards):** the support's +10% speed needs a change to shared movement and prediction, [U-050](U-050.md); choosing any free slot at join (owner decision D-8) is [U-051](U-051.md). Joining still takes the lowest free slot. The cleanup of the now-unused `class` room command on the wire waits for the next protocol bump.
- No playtest and no owner verdict on the loadouts' balance.
