# U-072 — Campaign flow: which mission is next, mission select and the debrief

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-071](U-071.md), 2026-10-01.

## Problem / outcome

The campaign file records `completedMissions`, but nothing chooses what is played next: the lobby lists one hard-coded
world and finishing a mission only shows the after-action stats. A campaign needs an order, a way to pick the next
mission (or a choice of two) and a short briefing and debrief between them.

## Scope

INBOX until D3 (structure) and D9 (debrief) in the design doc are answered. Proposed: a campaign definition as data (an
ordered list of mission ids with optional unlock conditions); the host offers the first mission not completed, or the
available ones; the lobby shows them with their briefing text; finishing a mission marks it complete and shows the
debrief (the stats screen plus a few lines of authored text) before returning to the lobby. The existing campaign file
format is extended additively (the U-060 approach).

## Start here

`server/src/persistence/CampaignDatabase.ts` (`completedMissions`), `client/src/ui/Lobby.ts` and `RoomLobby.ts`,
`server/src/session/Session.ts` (`campaignCompletedMissions`, mission end handling), the after-action screen
(`client/src/ui/scoreboard.ts`).

## Acceptance criteria

- [ ] A campaign is data; adding a mission to it needs no code.
- [ ] A new campaign starts at the first mission; a finished mission unlocks the next and the lobby offers it.
- [ ] A host restarted mid-campaign resumes at the right mission (campaign-file test).
- [ ] The briefing and debrief text are authored per mission, not hard-coded.

## Handoff / evidence

Not started. Scope recorded only; nothing is claimed.
