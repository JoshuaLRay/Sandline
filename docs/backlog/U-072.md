# U-072 — Campaign flow: campaign and replay runs, mission select and the debrief

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-071](U-071.md), owner decisions 2026-10-01.

## Problem / outcome

The campaign file records `completedMissions`, but nothing chooses what is played next: the lobby lists one hard-coded
world and finishing a mission only shows the after-action stats. A campaign needs an order, a way to pick the next
mission (or a choice of two) and a short briefing and debrief between them.

## Scope

Per the owner's decisions (design doc D3, D7): the campaign is a **straight line**; after each mission, completed *or
failed*, the **team leader** (design doc Q2) chooses between a **campaign run** of the newest mission the campaign has
reached and a **replay run** of any mission already beaten. The two runs keep **separate prisoner pools**: a character
captured in a campaign run is rescued only in the next campaign-run mission, one captured in a replay run only in the
next replay run. The campaign is data (an ordered list of mission ids); the lobby offers the choice with each mission's
briefing text; finishing a mission marks it complete and shows the debrief (the stats screen plus a few authored lines)
before the choice. A failed campaign run offers a retry or a replay, never skipping ahead (Q3). The campaign file is
extended additively (the U-060 approach): a prisoner pool per run type.

**Decided 2026-10-01:** the team leader is the **room's host** (Q2: not slot 0); a failed campaign run lets the host retry the same mission or choose a replay run, never skip ahead (Q3). Loadout carry-over is U-077; the three-way restart menu is U-078.

## Start here

`server/src/persistence/CampaignDatabase.ts` (`completedMissions`), `client/src/ui/Lobby.ts` and `RoomLobby.ts`,
`server/src/session/Session.ts` (`campaignCompletedMissions`, mission end handling), the after-action screen
(`client/src/ui/scoreboard.ts`).

## Acceptance criteria

- [ ] A campaign is data; adding a mission to it needs no code.
- [ ] A new campaign starts at the first mission; the leader chooses a campaign run of the newest mission or a replay run of any beaten one, after a completion or a failure.
- [ ] Prisoners are kept in separate pools by run type and rescued only in the same kind of run.
- [ ] A host restarted mid-campaign resumes at the right mission (campaign-file test).
- [ ] The briefing and debrief text are authored per mission, not hard-coded.
