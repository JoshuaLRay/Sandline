# U-030 — Keep downed and dead characters facing the same direction

Epic: **Character state**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-27](2026-09-27-feedback.md).

## Problem / outcome

"Downed and dead characters should not be able to rotate. They can rotate the camera, but not the character." Before this task the server kept writing `slot.yaw` from input for downed and dead slots, and the local body followed the camera. (The card body was previously a copy of U-031's text; corrected here.)

## Scope

Body heading is frozen at the heading held when the character went down or died; the camera view stays free. Proposed default (owner did not specify): the body keeps the last alive heading. Mounted-gun aiming and enemy AI facing are untouched.

## Start here

- `packages/server/src/session/Session.ts` — `applyInput` (aim write) and the per-tick `slot.yaw = slot.input.yaw`
- `packages/client/src/main.ts` — local `player.rotation.y`
- `packages/client/src/character/remoteSoldiers.ts` renders replicated yaw, so remote bodies follow the server.

## Acceptance criteria

- [x] A downed character's replicated yaw does not change when its player keeps turning.
- [x] A dead character's replicated yaw does not change.
- [x] Reviving restores turning.
- [x] The local body holds its heading while downed or dead; the camera still rotates (code change only, see below).

## Verification

`Session.test.ts` "Session body facing when down (U-030)": both new tests fail without the fix and pass with it.
