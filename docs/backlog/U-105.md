# U-105 — Distinct campaign lanes and per-map creation records

Epic: Map design. Status, priority and work link live in [BACKLOG.md](../../BACKLOG.md).
Source: owner request, 2026-10-04: lanes can currently be switched anywhere; write
an overarching map/mission markdown and one for each map, with distinct primary
assault, overlook/support and narrower isolated flank routes, then create a PR.

## Outcome and scope

Document the shared campaign creation rules, concrete Qalat rework and reusable
map record. Routes 1 and 2 may have several named connections; route 3 has zero
by default and at most one justified exception. Qalat chooses zero. Only Qalat
is currently a designed campaign map; missions 2–10 get their own record when
designed, without inventing their stories now. Legacy QA worlds are indexed as
outside this campaign rework.

This is a documentation PR. Actual level, collision, nav, encounter and gameplay
changes remain a separate implementation task using the new acceptance plan.
Keep prior owner playtest and headless-completion limitations visible.

## Acceptance criteria

- [x] Shared standard distinguishes physical separation from visual lane labels.
- [x] Route roles, connection policy, support angles and narrow-flank costs defined.
- [x] Qalat has a topology, explicit crossing register, boundaries, widths and
  approach/return/escort/tank constraints; design defaults are labelled honestly.
- [x] A reusable map template and index cover future maps and identify legacy QA scope.
- [x] Campaign, mission brief and authoring entry point link the new documents;
  outdated equal-width language is explicitly superseded.
- [x] Validation covers both legal routes and illegal shortcuts; no gameplay or
  owner acceptance claim is made by documentation alone.
