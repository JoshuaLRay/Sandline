# U-025 — Assign bot command authority to human players

Epic: **Squad command**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-26](2026-09-26-feedback.md).

## Problem / outcome

The squad needs explicit human command ownership for bots. Every bot must always have a human commander, and players need to be able to assign any bot to any human player.

## Scope

Implement server-authoritative commander assignment for bot-controlled squad slots and the player-facing assignment control. At campaign start, assign every bot to the human in the lowest-numbered occupied slot. Any connected human may reassign any bot to any connected human, including themselves. A bot must never be left without a valid human commander. Preserve assignments while the campaign runs and reconcile them when players join or leave. If the last human disconnects, pause campaign simulation until a human returns; bots cannot continue without a human commander. Keep assignment separate from who currently possesses a character.

## Acceptance criteria

- [ ] At campaign start with one or more humans, every bot is assigned to the lowest-numbered human slot.
- [ ] Any connected human can assign any bot to any connected human; server validation rejects nonexistent, disconnected, or human-occupied targets.
- [ ] The server maintains exactly one valid human commander for every bot across joins, leaves, reconnects, and reassignment.
- [ ] When a commander leaves, their bots are assigned to the lowest-numbered remaining human; when no human remains, simulation pauses until one returns.
- [ ] Assignment state is replicated to clients and the UI clearly shows each bot's commander.
- [ ] Reassignment is covered by server/session tests, including invalid requests and commander disconnect; the headless multiplayer integration test verifies replicated state.
