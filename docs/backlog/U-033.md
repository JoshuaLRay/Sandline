# U-033 — End the mission when a squad character dies

Epic: **Mission**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-27](2026-09-27-feedback.md).

## Problem / outcome

The owner wants a character's death to end the mission and return play to the last checkpoint. Being downed is not the same as dying; a downed character who can still be revived has not yet triggered mission failure.

The owner's wording does not specify whether the failure rule applies to every squad character (human-controlled and bot-controlled) or only the player-controlled character. Confirm this boundary against the persistent six-character roster before implementation; do not silently change the rule.

## Scope

When the applicable squad character reaches the authoritative dead state, fail the current mission and restore it from its most recent checkpoint. Preserve the existing checkpoint's mission/world reset semantics. Keep downed/revivable characters in the existing downed lifecycle unless they reach death.

## Start here

Confirm the current state and checkpoint paths before editing; these are investigation entry points.

- `packages/server/src/session/Session.ts` — mission lifecycle, health transitions and checkpoint handling
- `packages/shared/src` — health/death state and mission messages
- `packages/server/src/ai` — bot-controlled squad character state
- `data/scripts` — mission checkpoint transitions

## Acceptance criteria

- [x] A squad character reaching the authoritative dead state ends the current mission; downed-but-revivable state alone does not.
- [x] Mission failure returns play to the last checkpoint, preserving the current checkpoint's intended reset behavior for mission state, enemies and player state.
- [x] The applicable set of characters (human-controlled, bot-controlled or both) is explicit and consistent with the owner's six-character roster.
- [x] A single death produces one failure/retry transition, without duplicate checkpoint loads or stale control/mission state.
- [x] Deterministic tests cover death before and after a checkpoint, downed then revived, and downed then dead; relevant mission/session tests and `pnpm verify` pass.

## Verification

Exercise authoritative alive → downed → revived and alive → downed → dead transitions in a hosted-session or mission fixture, both before and after a checkpoint. Verify the mission returns to that checkpoint once and no other character loss or retry path is triggered.

## Handoff / evidence

Branch `task/U-033-death-ends-mission`. No gameplay change was needed: owner commit #180 (2026-09-29) already implements the rule, and this task pins it with tests and resolves the card's open questions from it.
- Applicable set (from #180, `mission.ts` `soldierDead`): **any of the six squad slots**, human-controlled or bot-controlled. The mission fails with reason `soldier-dead` on the first authoritative death; downed alone fails nothing, and all six downed fails as `all-downed`.
- "Return to the last checkpoint": failure shows the reason and restart choices, and `MissionRestart` restores the latest completed-objective checkpoint (or the start with `full`). It is a player choice, not an automatic reload; this is the behaviour #180 chose and I did not change it. If you want an automatic reload, that is a new card.
- New tests in `session/mission.test.ts`: downed then revived (no failure); downed then dead on a bot-held slot (fails once, a second death adds no second failure); death before any checkpoint then restart (attempt 2, objective 0, spawn points, everyone at full health). Existing tests already cover death after a checkpoint and restart from it.
- `pnpm verify` and CI: see the PR.
