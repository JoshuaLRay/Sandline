# U-091 — Spectate the escorted character

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-075](U-075.md) (the spectate acceptance criterion), owner decision 2026-10-01 that the escorted character is spectatable.

## Problem / outcome

A player (a dead or spectating one) can watch the escorted character. U-075 replicates him to every client, but the spectate path is slot-indexed throughout, so he cannot be picked.

## Scope

Pick a way to name him on the spectate wire and in the UI: a sentinel slot value (slot 7 fits `SwitchCharacter`'s and `Spectating`'s 3 bits; the server maps it to his netId where the per-client view is centred, `Session.ts` near the `spectators` map) or a netId field. Make the desktop and mobile spectate controls (`ui/mobileSpectate.ts`, `commandModel.ts`, `NetClient`) include him as a last stop in the cycle, drawn with his name from the mission. A protocol change bumps the version and has a round-trip test. Not in scope: ordering him individually (order addresses name slots 0–5).

## Acceptance criteria

- [x] A spectator can pick to the escorted character and sees from him; the camera follows him.
- [x] Without an escorted character the cycle is unchanged (the six-slot tests pass).
- [x] No protocol change was needed: the spectate wire already carries a three-bit slot, so the escorted character is the value `ESCORT_SPECTATE_SLOT` (6, the first past the six slots). No version bump.
- [x] `pnpm verify` green.

## Handoff / evidence

Implemented, in REVIEW (the PR is the evidence).

- Server: `SwitchCharacter { slot: 6, spectate }` is the escorted character (`ESCORT_SPECTATE_SLOT`, exported from `shared`); refused when the mission has none; no takeover, no seat change (a human's seat runs on its AI as for any spectate). The per-client view is centred on him (falling back to the spectator's own soldier if he is gone). `switch.test.ts` covers it, refusal and no takeover included.
- Client: the pause menu has "Spectate the prisoner" when he is in view (`NetClient.escortNetId`); the third-person camera follows him; the banner says so; the takeover keys do nothing for him. Mobile's spectate cycle is **not** changed (it is roster-based): a follow-up if wanted.
- Not claimed: a playtest of the view from him.
