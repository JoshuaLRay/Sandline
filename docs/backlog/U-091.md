# U-091 — Spectate the escorted character

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-075](U-075.md) (the spectate acceptance criterion), owner decision 2026-10-01 that the escorted character is spectatable.

## Problem / outcome

A player (a dead or spectating one) can watch the escorted character. U-075 replicates him to every client, but the spectate path is slot-indexed throughout, so he cannot be picked.

## Scope

Pick a way to name him on the spectate wire and in the UI: a sentinel slot value (slot 7 fits `SwitchCharacter`'s and `Spectating`'s 3 bits; the server maps it to his netId where the per-client view is centred, `Session.ts` near the `spectators` map) or a netId field. Make the desktop and mobile spectate controls (`ui/mobileSpectate.ts`, `commandModel.ts`, `NetClient`) include him as a last stop in the cycle, drawn with his name from the mission. A protocol change bumps the version and has a round-trip test. Not in scope: ordering him individually (order addresses name slots 0–5).

## Acceptance criteria

- [ ] A spectator can cycle to the escorted character and sees from him; the camera follows him.
- [ ] Without an escorted character the cycle is unchanged (the six-slot tests pass).
- [ ] A protocol change has a round-trip test and a version bump.
- [ ] `pnpm verify` green.
