# U-070 — Tank look and HUD: placeholder mesh, tell and arrival warning

Epic: **Mission / vehicle combat**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-035](U-035.md), owner decisions 2026-09-30 (all the proposed defaults).

## Problem / outcome

Players can see and read the tank, per [U-035](U-035.md).

## Scope

- A code-built placeholder mesh (hull, turret, barrel, tracks) in the same style as the other stand-in models, sized from the hitbox; real art comes later.
- Turret and barrel aim follow the replicated yaws; a muzzle flash and the cannon's tell; a destroyed tank leaves a wreck mesh.
- HUD: the arrival warning and the tank's health/armour marker when targeted; a compass marker.
- Sounds reuse existing cues (no new voice lines, ADR-017); an engine-rumble cue is a follow-up if wanted.
- Client tests for the model state and the HUD text.

## Acceptance criteria

- [x] The tank renders from the snapshot with the turret following its yaw.
- [x] The cannon's tell and muzzle flash show; a dead tank shows a wreck.
- [x] The arrival warning and the compass marker appear.
- [x] Client tests cover the model and HUD state.

## Handoff / evidence

Implemented on `task/U-070-tank-look`; awaiting review. No owner playtest verdict is claimed: how it looks in the game, and whether the tell reads, are the owner's to judge.

**What changed.**
- `character/tankLook.ts` (pure): the turret's yaw eased toward the replicated one at 1.25 x its turn rate (the wire carries it as a state, not a position), drawn relative to the hull; the tell (a pulsing 0.6–1 glow while `aiming`); the flash (0.12 s when the lock ends on a living tank, which is when the server fires, never for one killed in its tell); `wreck` for a dead tank; `tankTargetView` for the HUD.
- `character/tankModel.ts`: the code-built mesh (hull box, two track boxes, turret box, barrel cylinder, a lock lamp, a muzzle flash), dimensions from the `vehicle` block; charred materials for a wreck. `TankModels` draws every vehicle-archetype enemy and removes it when it leaves; its hull and turret boxes join `shootable`, so the crosshair can hit it (`netIdOf`). `RemoteSoldiers.update` skips vehicle archetypes so a tank is no longer drawn as a soldier.
- HUD: a target panel above the reticle (health label, bar, armour line) while the crosshair is on a tank; a `Tank` marker on the compass for a living one; `NetClient.remoteHealth(netId)` (health and maximum, kept across a partial delta). The arrival warning is the message and callout mission-01's `tank-arrives` event already sends (U-069); there is no second one.
- Sounds: none added. The shell's own sounds are the rocket's existing ones; an engine rumble is a follow-up.

**Evidence.** `character/tankLook.test.ts` (8) and `character/tankModel.test.ts` (5, through a real `NetClient` and scene: drawn as a tank not a soldier, hull heading, turret apart from the hull, lamp/flash/wreck, aim list and removal, health). `pnpm verify` and the CI jobs: see the PR.

**Not here.** Real art; an engine cue; a tank in the in-page QA scene; the compass marker and the target panel are wired in `main.ts`, which has no test harness, so they are covered by the pure functions they call only.
