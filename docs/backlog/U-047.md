# U-047 — Health kits

Epic: **Controls**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-044](U-044.md), owner direction and answers, 2026-09-29.

## Problem / outcome

Slot 6 holds health kits. Using one takes **10 seconds** and can target yourself or another character. It brings a **downed** character to **half health** and anyone else to **full health**. **A downed character cannot apply one to themselves; another character must.**

## Owner decisions (2026-09-29)

**3 kits per character.** The **Support gets a 20% discount on all interactions**, so its kit takes **8 s** (10 × 0.8); everyone else takes 10 s. The multiplier is U-049's; this card uses it.

## Scope

A new server-authoritative item: count per character, an apply interaction on a target within reach, progress and cancel rules, and the heal rules above. Interaction with the existing hold-E revive (3 s, T-2.15) is undecided: proposal is that the kit is a second, slower, healing route and hold-E stays. Bots use kits under the same rules. Each character starts with **3 kits** (owner-decided). Whether kits can be re-supplied is UNKNOWN; propose no re-supply.

## Start here

`packages/server/src/session/Session.ts` (revive interaction, pouch state), `packages/shared/src/data/damage.json`, `packages/shared/src/data/classes.json`, `packages/shared/src/sim/damage.ts`.

## Acceptance criteria

- [x] Applying takes 10 s (8 s for the Support once U-049 lands: `kitSeconds` is the one place it scales), is interrupted by moving away, damage or switching, and does nothing if the kit count is 0.
- [x] A downed target goes to half health; any other target to full health; neither can exceed max.
- [x] A downed character cannot self-apply; a mate can apply to them.
- [x] Counts are per character, survive reconnect and possession, reset on retry as other pouch items do, and are data.
- [ ] Bots can apply a kit to a downed mate. **Moved to U-053** (a bot behaviour, separate from the item; bots still revive with the hold-E route).

## Verification

Server tests for each rule and the interruptions, a hosted-session test with a downed target, `pnpm verify`. Numbers are placeholders until playtested.

## Handoff / evidence

Implemented on `task/U-047-health-kits`; awaiting review. Numbers are placeholders until playtested; no owner verdict is claimed.

**What changed.** Slot 6 draws the kits (`Equip` code `KIT_EQUIP_ITEM`; others see one more pouch item in hand, drawn as bare hands until a model exists). Holding the trigger with them in hand applies one: the target is the nearest downed mate in reach (1.5 m), else the nearest hurt mate, else the soldier themselves; it runs `damage.json` `kit.seconds` (10 s), and letting go, putting them away, taking damage, the target leaving reach or changing state, all cancel it (progress resets). A downed target goes to `kit.downedHealthFraction` (half) of max, anyone else to full; a downed soldier cannot apply one at all. Spent on completion (full-health targets spend nothing). The Weapon component gains `kits` and `kitProgress` (protocol 48): the page shows a "Health kit" row with the count and feeds the progress to the reload bar. Counts are per character (`classes.json` `healthKits`, default 3) and reset with the pouch on a retry or respawn.

**Evidence.** `packages/client/src/weapons/healthKit.test.ts` (10 tests over loopback: self, progress on the wire, cancel, damage, hurt mate before self, out of reach, downed mate to half at the price of one kit, downed cannot apply, none/gun in hand, full health spends nothing), `damage.test.ts` (`applyKit`), `classes.test.ts`.

**Proposals (labelled, reversible).** The target is chosen by the host (downed mate, hurt mate, self), not aimed; the kit is a second, slower healing route and hold-E revive is unchanged; no re-supply. A completed downed-mate kit credits the applier with a revive (XP and stat). Bots do not use kits yet (U-053).
