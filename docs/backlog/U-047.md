# U-047 — Health kits

Epic: **Controls**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-044](U-044.md), owner direction and answers, 2026-09-29.

## Problem / outcome

Slot 6 holds health kits. Using one takes **10 seconds** and can target yourself or another character. It brings a **downed** character to **half health** and anyone else to **full health**. **A downed character cannot apply one to themselves; another character must.**

## Scope

A new server-authoritative item: count per character, an apply interaction on a target within reach, progress and cancel rules, and the heal rules above. Interaction with the existing hold-E revive (3 s, T-2.15) is undecided: proposal is that the kit is a second, slower, healing route and hold-E stays. Bots use kits under the same rules. The number of kits each character starts with, and whether they can be re-supplied, are UNKNOWN; the implementer should ship a data default clearly labelled a proposal.

## Start here

`packages/server/src/session/Session.ts` (revive interaction, pouch state), `packages/shared/src/data/damage.json`, `packages/shared/src/data/classes.json`, `packages/shared/src/sim/damage.ts`.

## Acceptance criteria

- [ ] Applying takes 10 s, is interrupted by moving away, damage or switching, and does nothing if the kit count is 0.
- [ ] A downed target goes to half health; any other target to full health; neither can exceed max.
- [ ] A downed character cannot self-apply; a mate can apply to them.
- [ ] Counts are per character, survive reconnect and possession, reset on retry as other pouch items do, and are data.
- [ ] Bots can apply a kit to a downed mate.

## Verification

Server tests for each rule and the interruptions, a hosted-session test with a downed target, `pnpm verify`. Numbers are placeholders until playtested.

## Handoff / evidence

Not started. BLOCKED on U-045 and on the owner's kit counts.
