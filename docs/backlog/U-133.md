# U-133 — Authoritative cache use, replication and checkpoint stock

Epic: Map implementation. Status, dependencies and work live in [BACKLOG.md](../../BACKLOG.md).
Source: implementation leaf of [U-112](U-112.md), Mission 1 specification §12/§14.

## Scope

Consume U-132's static cache declarations and transfer rules in Session. Validate
supported physical placement without moving feet to another floor. A seated,
living soldier explicitly selects an item and holds uninterrupted use for 1 s
within 2 m with same-floor reach and LOS. Reject unavailable/incompatible choices
without starting time or consuming stock. Respect existing timed-interaction
rules, including the Support's interaction multiplier; document its effect.

Serialize completion against current server-owned stock/capacities; never commit
a stale preview. Add a dedicated protocol/state contract without weapon pickup
IDs. Replicate IDs, feet, remaining stock and interaction progress, including
empty caches. Durable saves and checkpoint retries restore both cache and squad
inventories together; reconnect never replenishes. Full restart rebuilds authored
stock. Preserve old scripts/saves and existing interaction priorities.

Client choice/presentation is U-134. Production placements/counts are U-117.
Split further before claiming if source inspection exceeds one focused PR.

## Acceptance and verification

- Same-floor/LOS/distance/timing/cancellation and capacity changes during use

  progress, exhausted scenery, reconnect and stale/forged requests.
- Retry and JSON host reload restore paired squad/cache inventories; repeated
  restore and event execution never replenish stock. Legacy saves remain valid.
- Focused regressions, `pnpm verify`, applicable budgets/generators and all four
  latest-head CI jobs pass. Preserve human gates and record actual results.

## Implementation evidence

Fresh main was `83366051f6b2013c34d42631652fb9cd5551db06`, with U-132/#307
and U-135/#308 accepted and merged. U-133 was the first dependency-eligible
leaf. Open #310 owns U-138 and U-114's U-138–U-141 split; no construction work
from that branch is duplicated here. U-136's dependency-only row was promoted
to READY from the actual #308 merge evidence.

- Session validates supported feet/standing clearance and bounded nav projection
  without relocating the cache. Use requires a seated living soldier, explicit
  item choice, held E, 3D feet distance ≤2 m, same floor and eye-to-cache LOS.
  One use takes 30 ticks; the Support's existing 0.8 multiplier takes 24 ticks
  (0.8 s) in class sessions. Free QA sessions keep their existing capacities and
  1× multiplier. Real release, silence beyond the existing five-tick input latch,
  lost reach/sight/capacity, downing/death, mounted use, spectating, departure or
  seat change cancels. A completed choice cannot repeat merely because E stays
  held. Revive, mount, charge/weapon pickup, upload and rescue priorities remain.
- Every completion recomputes the transfer against live host stock and inventory
  in stable slot order. Concurrent kit, frag and differently sized primary-ammo
  users cannot overdraw. Full/incompatible/empty attempts start no timer and
  consume no stock. Kit supply replenishes inventory without healing; equipment
  identities and held/stowed gun identities remain intact.
- Protocol 66 adds `SupplySelect`, incremental/full `Supplies`, and
  `SupplyProgress`, with no pickup IDs. Request IDs increase per connection;
  stale/replayed choices are ignored and forged server-state messages are refused
  by the connection layer. IDs/lists/item codes/stock integers/progress are
  bounded, including oversized LEB128 values that would otherwise wrap to zero.
  Timed progress travels at 10 Hz, with immediate choice/cancellation/completion
  changes. Exhausted caches keep their ID, feet and zero stock. `NetClient`
  consumes this state and exposes a choice API; reconnect clears/resends state
  and never resumes a hold or recreates stock.
- Checkpoint-world format 1 gains optional cache stocks, saved alongside all six
  squad inventories. Retry and JSON/database host reload restore kits, rockets,
  primary ammunition and cache pools together. Matching the complete authored
  ID set and bounded initial stock is checked before soldier inventory restore.
  Repeated restore or script execution does not add inventory. Full restart
  returns to authored stock and U-135's original mission-start squad inventory;
  legacy cache-less worlds remain valid.
