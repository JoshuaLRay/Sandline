# U-077 — Carry weapons, ammo and gear to the next mission; pickups replace the slot

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: owner decisions on the campaign design, 2026-10-01 ([design doc](../design/CAMPAIGN.md)).

## Problem / outcome

Today every mission starts from the class loadout and only rank and XP persist. The owner wants weapons, ammo and gear to carry, with a pickup replacing the gear in the character's current slot, and replay runs as the way to obtain other weapons.

## Scope

Proposal: at mission completion the campaign file stores each soldier's loadout (the `SlotCheckpoint` shape U-052 already captures: guns, rounds in each, pouch, kits, equipment); the next mission starts from it. A **replay run** starts from the campaign's loadout too, and the loadout it ends with is kept for the *replay* (the owner's wish is to go back and fetch other weapons for the squad), so replays write a loadout to the campaign file; **Decided 2026-10-01 (owner's defaults):** a campaign run carries weapons, ammo and gear forward and a pickup replaces the slot; a **replay run starts from the mission's default loadout** and may fetch other weapons on the map. *Inference to confirm:* what a replay ends with is kept for the campaign (D6: replaying is how players fetch different weapons for the squad), so a campaign run starts from the loadout the campaign last holds, replay pickups included. Say if a replay should keep nothing. A pickup replaces the item in the slot it would fill (primary for a primary, and so on; U-052's left-handed rules still apply). A restart or retry returns to the loadout the mission started with, never to a half-spent state. Rank and XP are untouched (D6).

## Start here

`SlotCheckpoint` and `checkpointSlot` in `Session.ts`, `CampaignDatabase.ts` (soldiers), U-052's pickup rules (`takePickupAt`), `data/classes.json` (the fixed class loadouts, which become the first mission's start).

## Acceptance criteria

- [x] A campaign file carries each soldier's loadout from a completed mission into the next.
- [x] A pickup replaces the gear in the matching slot, with the existing handedness rule (unchanged U-052 behaviour, covered by its tests; the carried loadout is the same shape, so a pickup after a carry replaces the carried item).
- [x] A retry and a restart return to the mission's starting loadout.
- [x] A replay run's loadout rule is as the owner decides and is tested.
- [x] An older save with no loadout loads as it does now (class loadouts).

## Handoff / evidence

Implemented, in REVIEW (the PR is the evidence).

- `SoldierSave.loadout` (a `SlotCheckpoint`, additive, validated and dropped if malformed) is written when a mission is won, from what each soldier carries at that moment. A campaign run starts each soldier from it (`startLoadout`, applied after the class loadout, class-loadout rooms only); a retry or restart returns to it (`resetMissionWorld`), and a checkpoint retry still restores the checkpoint's own snapshot. An older save has none and starts from the class loadout. Health starts full.
- Replay runs start from the class (mission default) loadout. `data/campaign.json` `replayKeepsLoadout` (default true) says a replay's end loadout is kept for the campaign: the **inference flagged for the owner** (design doc D6). Set it false and a replay keeps nothing; `loadoutCarry.test.ts` covers both.
- Tests: `loadoutCarry.test.ts` (5), `CampaignDatabase.test.ts`, `campaign.test.ts`.
- Not claimed: a playtest of the feel (ammo carried, gear scarcity), nor the weapon-swap UI; this changes only what the next mission starts with.
