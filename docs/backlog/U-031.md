# U-031 — Exclude downed characters from enemy gunfire targets

Epic: **Enemy AI**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-27](2026-09-27-feedback.md).

## Problem / outcome

Downed characters should not be targeted by enemy fire at all. The enemy must choose another eligible target or stop firing when its current target becomes downed; a downed character may later be the subject of a separate capture interaction (U-032).

## Scope

Exclude downed squad characters from enemy firearm target acquisition and continued engagement. Cover target selection, target revalidation and any firing path that can keep shooting at a character after that character is downed. Preserve the existing rules for living targets and the distinct future prisoner capture interaction.

## Start here

Confirm the active paths before editing; these are investigation entry points.

- `packages/server/src/ai` — enemy target selection and combat behavior
- `packages/shared/src` — shared AI and vitality state
- `packages/server/src/session/Session.ts` — authoritative health/downed state and damage

## Acceptance criteria

- [x] An enemy does not acquire a downed character as a firearm target.
- [x] If the current target becomes downed, the enemy stops firing at that character and reselects an eligible living target or ceases fire.
- [x] The rule applies consistently to all enemy firearm behaviors, including any suppression/retarget path that otherwise continues firing at a downed character.
- [x] A downed character remains eligible for the separate capture behavior specified by U-032; firearm-target exclusion does not prevent capture interactions.
- [x] Deterministic AI regressions cover target acquisition and a target transitioning from alive to downed; relevant AI tests and `pnpm verify` pass.

## Verification

Use a deterministic enemy-AI fixture with more than one squad target, plus a case where the currently engaged target becomes downed. Verify no further enemy damage/fire is directed at the downed character and that living-target behavior remains intact.

## Handoff / evidence

Branch `task/U-031-no-fire-at-downed`.
- Cause (from code): `chooseTarget` in `shared/src/ai/memory.ts` deliberately fell back to the best downed target when nothing else was known (`downedFactor` 0), the memory's downed flag was only refreshed while the soldier was in sight, and `aiShoot` only excluded the dead.
- Fix: `chooseTarget` never returns a downed entry (the entry stays in memory for U-032's capture); `downedFactor` and its fallback are removed from `data/memory.json` and the schema; `Session.perceive` syncs the downed flag each think whether or not the soldier is visible; `aiShoot` only shoots an alive soldier, which stops the burst between brain thinks.
- Tests: `memory.test.ts` (never chosen, alive-to-downed-to-up), and `session/enemyDownedTarget.test.ts` (a real rifleman shoots a standing soldier, then drops target and fires at most one more round once it is down; fails without the fix: target stays set).
- `pnpm verify` passes locally (208 files, 2175 tests); CI results are on the PR. Grenade and MG actions read the same memory entry and already require `downed === false`.
- Not reproduced in a live mission; no human playtest verdict.
