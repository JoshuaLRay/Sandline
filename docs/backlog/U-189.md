# U-189 — Loot generation and acquisition

Epic: Loot and progression ([U-183](U-183.md)). Pillar: P8.
Size: L (split per source at claim time). Human verdict: batched in U-193.
Status, priority, dependencies and branch/PR live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-16 — required epic phase 6; "Loot opportunities should occur during missions, rather than only at the end."

## Problem / outcome

Items appear in missions from the approved sources (default: enemy drops,
authored world loot, hidden caches with per-run sockets, high-value targets,
objective rewards), generated on the host from seeded tables, and bank on
success.

## Scope

- Per-mission loot tables as data; seeded generation (`shared/src/math` PRNG,
  no `Math.random`); bad-luck protection per L-02; banking on mission success
  per L-03.
- Hidden-cache sockets in map records (MAP-MISSION-CREATION §2); HVT carriers
  using reserved archetypes where approved.
- Checkpoint and retry rules (LOOT-PROGRESSION §11): no re-drops, no duplication.

## Read first

- U-185 specification; `packages/shared/src/sim/events.ts` (`pickup`), `pickups.ts`, `data/scripts/*.json`
- [LOOT-PROGRESSION.md §5, §11](../design/LOOT-PROGRESSION.md)

## Acceptance criteria

- [ ] Each approved source yields items per its table; a fixed seed reproduces drops exactly.
- [ ] Items bank only on success; a retry or failure banks nothing new.
- [ ] Drops respect handedness and the carry rule for every character.

## Verification

Unit tests for tables and seeding; headless mission runs; `pnpm sim-run`; CI.
