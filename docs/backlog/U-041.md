# U-041 — Carry the roster weapons on the wire

Epic: **Squad**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-020](U-020.md) on 2026-09-29 (that card required splitting before READY: more than one substantial new weapon behavior, plus art, audio and wire changes).

## Problem / outcome

`WEAPON_IDS` (the wire order) has five entries and the Weapon/Pickup component fields are 2-3 bits wide, so no soldier or pickup can carry the LMG or the U-040 weapons. Nobody can be equipped with the roster's guns until they can be named on the wire.

## Scope

Append the roster weapons to `WEAPON_IDS`, widen the affected fields (`Weapon.index`, `Weapon.primary`, `Pickup.weapon`, the `Fire`/`Possessed` weapon fields), bump `PROTOCOL_VERSION`, and update the pickup and class validators. Append only, never renumber (ADR-009). Netcode change: needs headless integration coverage.

## Start here

`packages/shared/src/sim/weapons.ts` (`WEAPON_IDS`), `packages/shared/src/net/schema.ts`, `packages/shared/src/net/protocol.ts`, `packages/shared/src/sim/pickups.ts`, `packages/shared/src/sim/classes.ts`.

## Acceptance criteria

- [ ] Each roster weapon round-trips through the schema, the `Fire` message and a pickup.
- [ ] Existing indices are unchanged and old data still decodes as before; the protocol version is bumped with the reason recorded.
- [ ] Hosted-session integration test: a soldier holding each new weapon replicates to a client, and a dropped one becomes a pickup.

## Verification

Schema/protocol unit tests, the netcode integration suite and `pnpm verify`.
