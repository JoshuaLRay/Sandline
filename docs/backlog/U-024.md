### What was wrong (on `main`, 1c835eb)

- **The page kept its own count and never heard the server's.** Its grenades and rockets came from:
  - the data's defaults at start;
  - the class's pouch when the class changed;
  - the pouch in a U-026 switch.

  The snapshot carried the item in hand, but not how many were left.
- **T gave back what the server had not.** It called `throws.reset()`, which puts back the data's defaults: 3 frags and 2 rockets. A Marksman (1 frag, no rocket) was then offered throws the server refused. That is B-18.
- **Respawns did not refill the page.** The server refills the class pouch on a respawn, but the page's count only changed with the class, so it stayed spent.
- **A dropped player came back with a fresh pouch.** On the server, a drop cleared the player's class pick while the seat was held for their resume (T-4.18). The class rebalance then made the held seat whatever a bot would be, and gave it that class's fresh pouch, which the resumed player kept. Reproduced headless: a Marksman who had thrown their frag dropped, resumed within the grace, and came back a Team Leader with 2 frags and a rocket. Dropping and resuming refilled the grenades.

### Change

- **On the wire** (protocol 36): the snapshot's Weapon component gains one count per pouch item, in `PROJECTILE_IDS` order (`left_frag`, `left_rocket`, 3 bits each, `POUCH_COUNT_BITS`), appended after its fields (ADR-009). The server writes each soldier's pouch there. A test holds the data to what 3 bits carry: every projectile carried and every class pouch is 7 or fewer.
- **In the page:**
  - `NetClient.pouch` is our own soldier's counts from our snapshot; a `Possessed` switch sets them until the next snapshot.
  - Every tick, `ThrowQA.reconcile` follows them:
    - a throw of ours is spent at once and held as pending until the server's count for it drops, so it is neither shown back while the Throw is in flight nor counted twice once it lands;
    - a throw the server never takes (it refused it) lapses after `PENDING_HOLD_SECONDS` (1.5 s);
    - a rise (a respawn, a refill) is the server's to give, and clears what was pending.
- **T:**
  - in a hosted room it no longer touches the pouch, since a hosted room's is never the page's to refill;
  - on the in-page range, where T is explicitly the range's reset key, it asks the in-page server to refill (`LocalServer.refillPouch` → `Session.refillPouch`), and the page follows.
  - `ThrowQA.reset` puts back the data's pouch only before any server has spoken.
- **On the server:** a seat held for a dropped player keeps the player's class pick, and so its class and loadout, through the grace:
  - `reassignClasses` treats a held seat as its human;
  - a resume keeps the pick;
  - when the grace runs out unclaimed, the pick goes and the classes settle (`releaseLapsedSeats`, swept each step).
  - A room with nobody seated is paused (U-025), so there a hold does not run out.
