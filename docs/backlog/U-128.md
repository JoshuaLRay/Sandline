# U-128 — Review saved voice recordings in the browser

Epic: Audio. Status, priority, dependencies and work live in BACKLOG.md.
Source: owner request, 2026-10-05: listen to saved recordings from the site's voice recording section; explicitly authorized implementation and the proposed GitHub owner login.

## Problem / outcome

Contributors can preview a new take, but the owner currently needs Fly SSH/SFTP to inspect saved submissions. The owner should open a review link, sign in with GitHub and listen to private recordings in the browser.

## Scope

One focused PR: a review link on the contribution page; a same-origin review page on the intake host; GitHub OAuth restricted to JoshuaLRay's stable account ID; authenticated submission listing and audio streaming with seeking; logout and clear empty/error states. Existing recordings stay on the Fly volume. No automatic import, public audio, deletion or runtime voice changes.

- `packages/client/src/ui/VoiceSubmission.ts`
- `packages/server/src/voice/intake.ts`, `main.ts`, `session/SessionHost.ts`

## Acceptance criteria

- [x] The contribution page links to owner review, with GitHub login and logout.
- [x] Only the owner's GitHub account can list submissions or fetch clips; public invitations and contributor tokens cannot grant review access.
- [x] Saved contributor names, dates, completion status and section recordings are shown without exposing upload credentials.
- [x] Native audio controls play/seek saved clips, with a download fallback for unsupported formats.
- [x] Anonymous reads, invalid OAuth state, non-owner login, expired/logout sessions, invalid clip paths and ranges are covered by tests.
- [x] Missing review configuration leaves gameplay and contribution uploads usable, with a clear setup message. Setup and real-browser review steps are documented.

## Verification

HTTP integration tests with a mocked GitHub provider and actual playable audio fixtures; browser review/playback capture; `corepack pnpm verify` and client production build. Actual GitHub OAuth/Fly deployment and owner's listening judgement remain pending until credentials are configured.
