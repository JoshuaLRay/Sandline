# U-102 — Direct mobile commands and a framed orbit camera

Epic: Mobile. Status, priority, dependencies and branch/PR live in BACKLOG.md.
Source: 2026-10-03 owner request: “Mobile ux needs an upgrade. Camera and controls both need updated to something not so many taps, more like modern games”.

## Problem / outcome

Current mobile commander controls require opening recipient/order menus and double
tapping a scene point. The camera changes view angle without orbiting its focus,
so dragging can lose the watched soldier. Exact device/browser: UNKNOWN.

## Scope

One mobile UX PR: visible squad and order shortcuts, drag an order onto the scene,
or select an order then single tap to place; keep double tap as a shortcut.
A chest-centered orbit, pinch zoom, wider starting view and recenter button.
Preserve mobile spectator/commander scope (ADR-002), portrait/landscape zoom limits
and hidden crosshair. Desktop input and server authority stay unchanged.
Routine defaults: start at 6 m, pitch -0.35 radians; constrain orbit elevation and
shorten camera arm at scenery/floor. Placement acknowledges local submission,
not a server acceptance confirmation.

## Start here

`packages/client/src/ui/MobileCommand.ts`, `ui/mobileCommand.css`, mobile gestures
and spectator camera in `main.ts`, `camera/mobileOrbit.ts`.
`docs/design/mobile-spectator-commander.md`, ADR-002.

## Acceptance criteria

- [x] Watch/select an eligible bot directly from the squad strip.
- [x] Drag an order to the scene and release to send exactly once, without menus.
- [x] Tap an order then tap a scene point to place; ordinary drags/pinches cancel placement.
- [x] Cancelled gestures, control drops and invalid recipients never send commands.
- [x] Orbit and zoom keep the watched soldier framed, avoid scenery/floor and support recenter.
- [x] Secondary assignment/settings/leave controls and desktop behavior remain available.
- [x] Portrait/landscape emulation reviewed (390×844 and 844×390).
- [x] Owner real-device feel verdict.
