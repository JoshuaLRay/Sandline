# U-187 — Item data and equipment foundations

Epic: Loot and progression ([U-183](U-183.md)). Pillar: P8.
Size: L (split into leaves at claim time if over ~800 lines). Human verdict: none (engineering).
Status, priority, dependencies and branch/PR live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-16 — required epic phase 4 ("Item data and equipment foundations"), and ADR-024 decision 7.

## Problem / outcome

Weapons, projectiles and equipment are separate data sets addressed partly by
array index; saves store some of them by index. Outcome: one item model
(definitions with stable string ids, categories, size/slot, handedness
`right | left | any`, mounts) that existing weapons and equipment map onto
unchanged in behaviour, plus server-issued item instances, with saves migrated
off numeric indices.

## Scope

- `packages/shared/src/data/items/*.json` with zod schemas; existing ids kept.
- Instances on the host per U-186; ground pickups, soldier loadouts and
  checkpoints reference instances or stable ids, never indices.
- Save migration with fixtures for old campaigns (including legacy class saves).
- Behaviour-preserving: every existing test passes without retuning.
- Not in scope: generation, rarity, attachments (later phases).

- [ ] All weapons/projectiles/equipment defined as items; no gameplay change (all suites green, mission sim counts unchanged).

- [ ] Marsh's handedness enforced from item data; sidearms/launchers/knife per L-10.
- [ ] Wire impact handled with protocol bump if any.
