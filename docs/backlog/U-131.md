## Scope

Place staged reserve soldiers/tank at mission initialization, count them toward caps/budgets and allow ordinary damage while inactive. Script activation releases existing survivors with authored orders/path, never respawns dead members. Persist activation and one-shot state.

owner playtest acceptance or reduce the U-111 parent contract.

Implemented optional `staged` fixed-socket groups: inactive soldiers/tanks are
already present and replicated before input (or before ready-up grants input).
Start-trigger guard/POW sockets also initialize before input. Dormant members
take ordinary hitscan/blast damage and occupy caps; perception, brains, movement,
weapons, emplacement, lever and capture work wait for release. Existing triggers
and `spawn-group` actions release living members without changing health,
inventory, position or identity. Pre-killed members, including an entire tank
group, stay dead; destroy objectives recognise pre-activation destruction.

Soldier sockets may carry a one-way 3D `advance` route and the existing combat
region. Legs are validated against real nav and the intended floor; combat can
preempt the advance, which resumes its phase and holds the final point. Vehicle
sockets validate full hull/turret support, clearance, floor bounds and overlap;
their existing 3D group path validates from each exact socket. Tank weapons
start their cadence on release. No new wire fields or runtime dependencies.

Durable checkpoints persist dormant state, advance leg, vehicle path progress,
spawner placement/release, event one-shots and timer offsets. Restore runs before
initialization, preventing a fresh population on retry/host reload. Dead member
remap sentinels serialize as zero so a subsequent JSON checkpoint remains valid.
Legacy encounter/save shapes remain accepted; full restart rebuilds all members.

The real baked-nav fixture places 32 mixed guards across y0/y8/y16, four dormant
riflemen, an elevated dormant tank and a captive POW at both one- and six-human
budgets. It verifies exact feet/facing before tick zero, dormant behaviour,
real hitscan and blast damage, survivor-only release while watched, identical
wire IDs/no new spawn log entries, actual advance/tank movement, repeated
release, timer/phase/health retention, two JSON reloads after a death, retry,
full restart, lobby ready-up and a real resume-token reconnect. A pre-destroyed
tank completes its destroy objective without release or replacement. Separate
spawner regressions verify dormant cap pressure, fixed counts, idempotent init,
legacy queued-wave timing and failure instead of initial visible pop-in when
occupancy or the host cap prevents placement.
