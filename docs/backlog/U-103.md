# U-103 — Make aggression commands available on mobile

Epic: **Mobile / Squad command**. Status, priority and dependencies live in [BACKLOG.md](../../BACKLOG.md).
Source: owner, 2026-10-03: on mobile, wants to command the squad to be aggressive, neutral, or lay low; recently introduced controls cannot be used. Device/browser UNKNOWN.

## Problem / outcome

U-101 added Hold fire / Defensive / Aggressive selectors to the desktop Squad panel. The separate mobile command UI does not expose aggression controls or forward aggression commands. Mobile users need to set the existing policies for all commanded bots or an individual bot.

## Scope

Expose existing server policies in the mobile Squad menu, preserving approved names and behavior. Use the selected order recipient, show authoritative current state (including mixed group state), and prevent changes for unavailable recipients. No combat tuning or protocol changes.

## Start here

`packages/client/src/ui/MobileCommand.ts`, `mobileCommand.css`, `MobileCommand.browser.test.ts`, and mobile command wiring in `packages/client/src/main.ts`. Related: [U-101](U-101.md), [U-102](U-102.md).

## Acceptance criteria

- [x] Mobile Squad menu offers Aggressive, Defensive and Hold fire for all commanded bots and a selected bot.
- [x] A tap sends one addressed command without scene placement and cancels any armed movement order.
- [x] Selection reflects server state, including mixed groups and later updates.
- [x] Captured characters, other players’ bots and humans cannot be commanded; the spectator’s own AI-controlled character remains eligible.
- [x] Controls are touch-sized and reachable in portrait and landscape.

## Verification

Browser regression tests for group/individual commands, policy replication, selection, eligibility and placement cancellation; `pnpm verify`. Physical mobile playtest remains pending.
