# U-088 — The campaign as data: order, titles, briefings and debriefs

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: split from [U-072](U-072.md) (leaf 1 of 3), owner decisions 2026-10-01.

## Problem / outcome

Nothing says which mission follows which: the lobby lists maps, and `completedMissions` in the campaign file is a set. The campaign needs an order and per-mission authored text (title, briefing, debrief), as data, so adding a mission to the campaign needs no code.

## Scope

`data/campaign.json`: `{ id, missions: [{ mission, title, briefing: [..], debrief: [..] }] }`, validated by hand-written checks like the other data files: every `mission` is a registered mission (`campaignRegistry`), no duplicates, non-empty title and text. A shared module with pure helpers: the order; the **newest mission reached** (the first not yet completed, or none when all are); the **beaten** missions in order; what a leader may choose after a mission (a campaign run of the newest, a replay of any beaten one; never a mission beyond the newest, so a failed campaign run offers the same mission again, Q3); a mission's briefing and debrief. The first entry is `mission-01` with text authored for the mission as it plays now; U-065 replaces it. Not in scope: the save file's run kinds (U-089), the choice screen and handoff (U-090).

## Start here

`shared/src/sim/campaignRegistry.ts` (what is registered, and how a throwaway list is tested), `docs/design/CAMPAIGN.md` (decisions D3, D6, Q2, Q3).

## Acceptance criteria

- [x] `data/campaign.json` exists, parses, and rejects an unknown mission, a duplicate, empty text and stray keys.
- [x] The helpers give the newest mission, the beaten ones and the options after a completion and after a failure, tested on a two- and a three-mission throwaway campaign.
- [x] Adding a mission to the campaign is one data entry (a test adds one and nothing else changes; `docs/COMMANDS.md` lists the step).
- [x] `pnpm verify` green (see the PR).

## Handoff / evidence

`shared/src/sim/campaign.ts` (exported from the package) with `data/campaign.json` (`season-1`, one entry: mission-01, with text for the mission as it plays today; U-065 replaces it). `parseCampaign(raw, known)` refuses an unknown mission, a repeat, empty text and stray keys. Helpers over a campaign and the completed set: `campaignOrder`, `newestMission` (the first not completed; null when the season is done), `beatenMissions`, `runOptions` (`{ campaign, replay }`), `isOffered(kind, mission, completed)` (never a mission beyond the newest, so a failed campaign run still offers the same mission: Q3), `campaignMission` (title, briefing, debrief). Completed missions outside the campaign are ignored.

`pnpm exec vitest run packages/shared/src/sim/campaign.test.ts`: 8 tests. `pnpm verify`: see the PR. Nothing is wired to the lobby or the save yet: that is U-089 and U-090.
