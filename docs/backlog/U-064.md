# U-064 — Captured characters in the slot picker, HUD and messages

Epic: **Campaign**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-032](U-032.md), owner decisions 2026-09-30 (all the proposed defaults, except that capture is allowed after 2 s down rather than 10 s).

## Problem / outcome

Players can see and understand that a character is a prisoner, per [U-032](U-032.md).

## Scope

- Slot picker/lobby: a captured character is greyed out with "Captured" and cannot be chosen; its reason is readable.
- HUD and scoreboard: a captured squadmate is marked; a capture in progress is announced to the squad ("Holloway is being taken") with the capturer marked, so the squad has a window to react.
- Messages/callouts on capture, on a cancelled capture, and on rescue; no voice lines are invented (ADR-017).
- Mobile is spectator-only: show the same state in spectate.

## Acceptance criteria

- [x] The picker refuses a captured character and says why.
- [x] The HUD and scoreboard show captured characters and a capture in progress.
- [x] Messages fire on capture, cancel and rescue, once each.
- [x] Client tests cover the picker and the model of the HUD state.

## Handoff / evidence

Implemented on `task/U-064-captured-ui`; awaiting review. No owner playtest verdict is claimed.

**What changed.**
- Wire: `RosterEntry.takenBy` (the capturer's net id while a hold has begun, else -1); `PROTOCOL_VERSION` 58. The roster is resent when a hold begins or ends.
- Server: `announceCaptures` says once "<Character> is being taken" (the hold has begun, per U-062 decision 2) and once "<Character> was not taken" if it ends without a capture; `captureCharacter` says "was taken prisoner", `freeCharacter` "was rescued". They use the existing squad notice line (`ScriptMessage`); no voice lines (ADR-017).
- Client: HUD squad rows and the Tab scoreboard mark "captured" / "being taken"; the capturer gets a red mark on the compass and in the world; the command list greys out a prisoner ("Captured — rescue them to play") and never offers take-over; the room lobby and squad panel mark it. Spectating uses the same roster, so spectators (and mobile) see the same state.

**Decision to confirm.** The pre-join character picker (U-051) cannot know who is held, since no room state exists before joining. A join that asked for a prisoner is seated elsewhere by the host (U-061) and the client now says why. Listing held characters in the picker itself would need a pre-join room query; say if wanted.
