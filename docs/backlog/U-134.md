## Scope

Present U-133's replicated cache stock and authoritative progress in the client.
Show explicit item choice when several types are compatible; each interaction
requests only the selected type. Show remaining stock, unavailable/incompatible
choices, timed-use feedback and an empty-state label. Exhausted boxes remain
visible scenery. Desktop uses the approved Tab mouse-access and held E controls;
interrupted holds cancel on the host. Mobile watches nearby cache stock and other
users' authoritative progress through the approved spectator/commander interface.
Mobile item choice/use is retained in [U-145](U-145.md), split before claiming:
U-133's desktop use path refuses spectator-held-E use, and the approved mobile design exposes
no soldier interaction input. This split does not waive U-112's mobile acceptance.

Use five representative caches in reproducible UI/session fixtures; production
placement and dressing are U-117/U-118. Split before claiming if asset/UI work
exceeds a focused PR. Do not fabricate owner visual or gameplay acceptance.

## Implementation evidence — PR #314

The normal gameplay HUD shows nearby caches on the viewed soldier's floor and
within 3D reach/LOS, with explicit one-type choices. Compatibility/capacity
previews reuse `transferSupply` and confirmed inventory; they never spend or
reserve stock. Only `SupplyProgress` selects a row or moves the progress bar.
Release E interrupts on the host; hiding the UI or changing its cache cancels
pending/accepted choices. An accepted cache remains selected while reachable,
even when another cache becomes nearer. Full/incompatible/depleted rows cannot
send a request. Other users' progress and subsequent stock changes stay visible.

Mobile and desktop spectators view stock/progress beside the watched soldier.
Mobile never sends a use request from this panel. U-145 retains implementation
and acceptance of the commander-resupply design approved on 2026-10-08.
Two instanced draws render all cache boxes, including
exhausted ones; no production placement, collision, nav, art or audio inputs
changed. The isolated five-cache fixture carries the representative §12 stock
on the greybox floor, not the future production locations.

## Owner review steps

1. Run `pnpm --filter @sandline/client dev --host 0.0.0.0`. Open
   `/supply-review.html` on the dev server for the live isolated Session fixture.
   Choose each of the five caches with its fixture control; stock persists when
   moving between them, while carried deficits reset for repeatable review.
2. At Cache 1, select each type. Hold E briefly and release: progress clears
   without a transfer. Select again and hold for one second: only that type
   changes. Primary ammo fills the missing 15 LMG rounds, consuming 0.15 magazine
   equivalent. Kit use restocks a charge rather than healing; rockets fill the
   existing two-round capacity. A full choice is disabled until capacity changes.
3. Inspect the captures above for concurrent progress, the resulting partial
   stock, full/incompatible/depleted rows and retained exhausted scenery. In
   production gameplay with authored caches, hold Tab for mouse choice, release
   Tab and hold E; release E, leave reach/LOS or pause to cancel.
4. On a physical phone open `/supply-review.html?mobile` and inspect all five
   caches. Review readability, scrolling, safe-area fit and the stock/progress
   captures at portrait and landscape sizes. This leaf provides spectator
   viewing; mobile item choice/use is pending U-145 and must not be marked passed.
5. Record the owner's presentation/play verdict separately. Production map
   placement/dressing and complete integrated mission acceptance remain
