# U-134 — Cache choice UI, use progress and stock presentation

Epic: Map implementation. Status, dependencies and work live in [BACKLOG.md](../../BACKLOG.md).
Source: implementation leaf of [U-112](U-112.md), Mission 1 specification §12.

## Scope

Present U-133's replicated cache stock and authoritative progress in the client.
Show explicit item choice when several types are compatible; each interaction
requests only the selected type. Show remaining stock, unavailable/incompatible
choices, timed-use feedback and an empty-state label. Exhausted boxes remain
visible scenery. Reuse approved desktop/mobile controls without hiding access
behind developer UI; interrupted holds cancel on the host.

Use five representative caches in reproducible UI/session fixtures; production
placement and dressing are U-117/U-118. Split before claiming if asset/UI work
exceeds a focused PR. Do not fabricate owner visual or gameplay acceptance.

## Acceptance and verification

- Desktop and mobile can choose among compatible items, start/interrupt use,
  and see host-authoritative stock/progress/empty state. Full/incompatible or
  depleted choices consume no time or stock; UI reflects contention updates.
- Reproducible browser captures and manual owner steps cover all three stock
  types, partial transfers, contention and exhausted scenery. Owner presentation
  and play quality verdicts remain separately pending until supplied.
- Focused UI/integration regressions, `pnpm verify`, client build, applicable
  budgets/generators and all four latest-head CI jobs pass; record real evidence.
