# U-032 — Capture downed characters as prisoners for next-mission rescue

Epic: **Campaign**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-27](2026-09-27-feedback.md).

## Problem / outcome

The owner wants an enemy to be able to capture a downed player character as a prisoner of war (PoW), with that character requiring rescue in the next mission. This is a new campaign mechanic; capture conditions, rescue objective details and persistence rules have not been specified.

## Scope

Decompose and implement an enemy capture interaction for a downed player character, persist the captured status into the next mission, and make that character recoverable through a rescue. A captured character is not killed by the capture and must not be available as a normal squad character before rescue. Define interruption, mission retry/checkpoint, and rescue success/failure behavior before treating the work as READY. Do not implement capture by allowing enemies to fire on a downed character; see U-031.

Confirm actual file paths and campaign persistence model before splitting executable leaves.

## Acceptance criteria

- [ ] Break this request into executable leaves with decisions recorded for capture eligibility, enemy approach/interaction, interruptibility, and what happens on mission retry.
- [ ] A successfully captured downed player character persists as a PoW into the following mission and cannot be selected for ordinary play until rescued.
- [ ] A rescue objective in the following mission can restore the captured character to the squad, with success and failure outcomes defined.
- [ ] Capture, retry, mission transition and rescue state remain consistent for all players and after reconnect/reload as supported by the campaign.
- [ ] Capturing a downed character does not inflict further enemy gunfire damage on that character.

## Verification

After decomposition, cover the capture interaction, checkpoint/retry and next-mission persistence, rescue success/failure, and multiplayer/reconnect behavior in deterministic tests. Use an end-to-end campaign scenario for mission transition; run `pnpm verify`.
