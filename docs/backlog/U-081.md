# U-081 — The cover search must not scale with the whole map

Epic: **Enemy AI**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-076](U-076.md), the large-map spike, 2026-10-01.

## Problem / outcome

With the cover search on, the server tick on a 10x map (three 40 m lanes by 480 m, 6,768 cover points) is 83–111 ms against a 33 ms budget, and 270–295 ms at 20x. With the cover points removed it is 2.8–3.3 ms. mission-01 (728 points) is fine, so nothing is wrong today; every larger campaign map would be.

## Scope

`CoverSystem.sightFrom` traces `protects(...)` for every cover point on the map against every box for each distinct threat eye (cached only by exact eye position, so a moving threat is a new entry every tick), before `search` has narrowed to the points near the asker. Make it cost what the query needs: (1) compute `protects` and the firing position lazily per point, only for points that pass the `maxPathM` distance prefilter; (2) index the points in a uniform grid so the prefilter does not scan the map; (3) keep the answers exactly the same (the cache and the optimistic ordering stay), so the existing cover tests and `sim-run --scenario cover-duel` and `pinned` give identical results. Re-run `pnpm spike:large-map 480` and record the new numbers on this card.

## Start here

`packages/server/src/ai/cover.ts` (`search`, `sightFrom`, `protects`, `firingPosition`), `packages/tools/src/spike-large-map.ts` (`COVER=none` shows the cost without it), the cover tests (`cover.test.ts`) and the T-3.19 cost test.

## Acceptance criteria

- [ ] The cover search returns exactly the choices it did (the cover, `cover-duel`, `pinned` and `mg` scenarios and tests unchanged).
- [ ] `pnpm spike:large-map 480` keeps the server step under about 10 ms with 40 enemies, and 960 under about 20 ms.
- [ ] mission-01's AI cost (`sim-run --scenario mission`) is not worse.
- [ ] A new test builds a large world and bounds the number of `protects` traces a query makes by the points near the asker.
