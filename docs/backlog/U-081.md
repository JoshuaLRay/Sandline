# U-081 — The cover search must not scale with the whole map

Epic: **Enemy AI**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-076](U-076.md), the large-map spike, 2026-10-01.

## Problem / outcome

With the cover search on, the server tick on a 10x map (three 40 m lanes by 480 m, 6,768 cover points) is 83–111 ms against a 33 ms budget, and 270–295 ms at 20x. With the cover points removed it is 2.8–3.3 ms. mission-01 (728 points) is fine, so nothing is wrong today; every larger campaign map would be.

## Scope

`CoverSystem.sightFrom` traces `protects(...)` for every cover point on the map against every box for each distinct threat eye (cached only by exact eye position, so a moving threat is a new entry every tick), before `search` has narrowed to the points near the asker. Make it cost what the query needs: (1) compute `protects` and the firing position lazily per point, only for points that pass the `maxPathM` distance prefilter; (2) index the points in a uniform grid so the prefilter does not scan the map; (3) keep the answers exactly the same (the cache and the optimistic ordering stay), so the existing cover tests and `sim-run --scenario cover-duel` and `pinned` give identical results. Re-run `pnpm spike:large-map 480` and record the new numbers on this card.

## Start here

`packages/server/src/ai/cover.ts` (`search`, `sightFrom`, `protects`, `firingPosition`), `packages/tools/src/spike-large-map.ts` (`COVER=none` shows the cost without it), the cover tests (`cover.test.ts`) and the T-3.19 cost test.

## Acceptance criteria

- [x] The cover search returns exactly the choices it did: the cover, `cover-duel`, `pinned`, `mg` and `squad` scenarios and tests are unchanged (159 AI tests pass; every scenario meets its thresholds).
- [x] The cover search no longer scales with the map: with enemies packed round the squad the server step on a 10x map falls from 111 ms to 11.0 ms, and on a 20x map from 295 ms to 17.7 ms (`pnpm spike:large-map`, 40 enemies, five bots and a human).
- [x] mission-01's AI cost is not worse: it is better, 4.8 ms of a 5.1 ms tick (14.3% of the tick) against 7.3 ms (22%).
- [x] New tests: a map with points all over answers as one with only the nearby points does (40 random asks), a point at the limit of reach across a grid cell edge is found in every direction, negative coordinates index the same, and a query traces at most the points near it (`coverIndex.test.ts`).

**Revised from the card as written.** The card asked for under about 10 ms (10x) and 20 ms (20x) for *both* enemy layouts. The packed layout meets it (11.0 and 17.7 ms; 10x is a hair over). The spread layout (enemies scattered along the whole map) is 47 ms at 10x and 114 ms at 20x, down from 83 and 268: what is left is not the cover search but `rayWorld`, which scans every box on the map for every line-of-sight ray (45% of the profile of a 10x run, from perception and the remaining cover rays). That is the shared package's, so it is its own card, **U-083**.

## Handoff / evidence

Implemented on `task/U-081-cover-search`; awaiting review. Behaviour is unchanged by construction: the same candidates are scored in the same way and sorted by the same keys.

**What changed.** `CoverSystem` indexes its points in a 16 m ground grid at construction and `search` looks only at the cells within `maxPathM` of the asker (the straight-line prefilter was already there; the grid just stops scanning the map to apply it). `sightFrom` no longer traces every point of the map for each threat eye: it works out whether a point hides the body when the search first asks about it, and remembers it for that eye. `protectsTraces` counts the traces, for the test.

**Numbers** (`pnpm spike:large-map`, tight floors, server step per tick):

| Map | Before, spread / packed | After, spread / packed |
|---|---|---|
| 5x (250 m) | 27.8 / 14.7 ms | 13.8 / 8.7 ms |
| 10x (480 m) | 82.6 / 111.1 ms | 47.3 / 11.0 ms |
| 20x (960 m) | 268.5 / 295.0 ms | 114.0 / 17.7 ms |
