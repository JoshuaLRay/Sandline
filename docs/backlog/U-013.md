# U-013 — Supply and process the real voice recordings

Epic: **Audio**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-26](2026-09-26-feedback.md), plus any legacy bug named below.

## Problem / outcome

The current pipeline has no source recordings. ADR-017 explicitly chooses consenting human recordings processed in code; the request for radio-like voices does not by itself authorize replacing that sourcing decision.

## Scope

Once recordings are supplied, validate consent, map required cues, run the existing processing pipeline and commit playable outputs. Extend treatment for radio/dialogue and enemy shouts. If the owner wants synthesized speech instead, first record that choice, source/provider and cost constraints in an ADR addendum; do not purchase or silently switch services.

## Acceptance criteria

- [ ] Actual playable voice clips, rather than chirps/test signals, cover radio, friendly hit/down/death and enemy engagement families.
- [ ] Each source has the provenance/consent required by ADR-017; enemy language, wording and delivery fit ADR-020 and are reviewed by someone who understands the chosen language.
- [ ] Outputs satisfy measured clipping/loudness/duration checks and asset budgets; regeneration is reproducible.
- [ ] The owner records a listening verdict for intelligibility and delivery.
