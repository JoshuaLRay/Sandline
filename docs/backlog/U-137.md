# U-137 — Record, submit and replay separate voice takes for every line

Epic: **Audio / contribution UX**. Status, priority and work live in [BACKLOG.md](../../BACKLOG.md).
Source: owner report, 2026-10-06: more than twenty apparently submitted clips resulted in only two saved recordings; requested a line list with contributor counts, quoted lines and parentheticals, Record/Stop, Submit, and a scrollable playback list. Explicitly authorized implementation and merge when green.

## Problem / outcome

The U-036 page records entire sections, retains only one local preview, requires a separate Upload action, then requires Finish. The intake replaces earlier uploads for the same section. These code paths explain how repeated takes can be discarded or overwritten; the exact sequence behind the owner's twenty clips is UNKNOWN.

## Scope

One focused change to the contribution page and private intake: separate, immutable line/style takes; immediate durable submission without a second Upload/Finish action; contributor-specific counts and replay restored with the browser's submission credential. Preserve existing section submissions, consent, invitation, limits, owner review and explicit offline import. Adapt import/processing to consume the new line files without assigning partial recordings to the wrong script lines. No recording is automatically published into gameplay.

## Acceptance criteria

- [x] All scripted line/style entries show this contributor's server-confirmed recording count; returning in the same browser restores saved counts and replay.
- [x] Tapping a line shows its quoted prompt and parenthetical direction, Record switching to Stop, Submit, and a scrollable list of every take for that line.
- [x] Playback pauses and is disabled during microphone acquisition, recording and stopping; navigation cannot switch the active line mid-recording.
- [x] Submit saves the take on the configured intake immediately, makes it available for owner review/import, and requires no Upload or Finish action. Multiple takes never overwrite each other, and retries do not duplicate a saved take.
- [x] Failed saves remain visibly unsubmitted and retryable. Unsaved takes survive line navigation and cannot masquerade as a saved count.
- [x] Contributor reads require that submission's credential; consent, origin restrictions, upload/storage limits and owner-only access to other contributors are preserved. Old section submissions remain readable/importable.
- [x] Owner review and the offline pipeline understand separately labelled line takes, including partial scripts.
