# U-029 — Keep downed and dead characters facing the same direction

Epic: **Character state**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [owner feedback, 2026-09-27](2026-09-27-feedback.md).

## Problem / outcome

When a character is downed or dead, the player should still be able to rotate the camera, but camera input must not rotate the character's body. The body keeps its existing facing while incapacitated.

The owner did not specify whether reviving a downed character restores normal body rotation immediately or through an animation; preserve the existing recovery behavior unless a separate decision is needed.

## Scope

Separate camera look from character-body rotation while the character is downed or dead. Apply the rule to player-controlled characters; confirm bot presentation and recovery behavior against existing state rules before implementation. Do not change camera movement or the character's facing on entering the downed/dead state.

## Start here

Confirm the active paths before editing; these are investigation entry points.

- `packages/client/src/main.ts` — input, camera and local character presentation
- `packages/shared/src` — character health/state and rotation interfaces
- `packages/server/src/session/Session.ts` — authoritative character state and replication

## Acceptance criteria

- [ ] While downed, camera yaw/pitch input changes the camera view but does not change the character body's facing.
- [ ] While dead, camera yaw/pitch input changes the camera view but does not change the character body's facing.
- [ ] Alive character rotation and camera control remain unchanged.
- [ ] A regression test covers camera look while downed and dead and verifies that replicated/presented body rotation remains fixed.
- [ ] Revive, death, respawn and checkpoint recovery do not leave rotation input incorrectly disabled or rotate the body as a side effect.

## Verification
