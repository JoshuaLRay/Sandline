# U-083 — Ray casts must not scan every box on the map

Epic: **Campaign design**. Status, priority and dependencies live only in [BACKLOG.md](../../BACKLOG.md).
Source: [U-081](U-081.md), 2026-10-01.

## Problem / outcome

After the cover search was indexed (U-081) a 10x map with enemies spread along it still costs 47 ms a tick (114 ms at 20x) against a 33 ms budget. A CPU profile of the run puts 45% in `rayWorld`, which tests every box in the world for every line-of-sight ray (it has a bounds reject but still loops over all boxes), from enemy perception, aim checks and the remaining cover rays. mission-01 (34 boxes) does not notice; a 700-box map does.

## Scope

Give `rayWorld` (and the collision queries that scan `World.boxes`, if the profile says so) a broad phase: a uniform ground grid of boxes, walked along the ray (a 2D DDA), so a ray tests only the boxes in the cells it crosses. The grid belongs to the box list, not to a caller: the session's `collisionBoxes` array is rebuilt in place when a script blocker is toggled, so the index must be rebuilt (or keyed to a version) whenever it changes, and a stale index must be impossible. Answers must be bit-identical to the scan (same hit, same distance, same face), so it is pure culling; shared-package rules apply (no `Math.hypot`/`atan2`, table trig only). Re-run `pnpm spike:large-map` and record the numbers.

## Start here

`packages/shared/src/sim/world.ts` (`rayWorld`, `WorldRay`), `server/src/ai/aim.ts` (`lineOfSight`), `Session.ts` (`collisionBoxes`, `setBlocker`), the CPU profile method on the U-081 card (`node --import tsx --cpu-prof`), `packages/shared/CLAUDE.md`.

## Acceptance criteria

- [ ] `rayWorld` returns exactly what it does now for any ray and any box list (a randomised comparison test against the scan, including rays that start inside a box, run along a face or have a zero component).
- [ ] A toggled script blocker is seen by the next ray (the index never goes stale).
- [ ] `pnpm spike:large-map` keeps the spread layout under about 15 ms at 10x and 30 ms at 20x.
- [ ] mission-01's `sim-run --scenario mission --seeds 3` and the parity tests are unchanged.
