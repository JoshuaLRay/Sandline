# Private controller CI and hosted rollback

The PC runner is registered only to private owner-only `JoshuaLRay/Private-CI-Controller`. This public source repository cannot schedule it. Owner review must cover the exact source, scripts, tests and dependencies before manual full-SHA dispatch. Immutable SHAs and workflow conditions are not malicious-code isolation boundaries. Never activate old direct-runner draft #379.

All four stable required checks remain `verify`, `streaming`, `parity-non-v8`, `mission`, now from private GitHub App **5384278**, `joshualray-private-ci-checks`. Its Windows-owner publisher independently validates full controller jobs/matrices, exact checkout, current PR head, run/attempt and required artifacts. Its merge gate rechecks latest App identity/results, head/base/mergeability and evidence; separate failed hosted required checks cannot be bypassed. Public branch rules should bind these exact checks to this App; private controller protection is not enforced on the current plan.

The controller retains mandatory pnpm verify and four total test shards, all assets/packs, streaming load/preview/map/frame budgets, five independent generation/capture members and every artifact, Chromium/Firefox/WebKit non-V8 parity and all three mission-seed workloads. A single runner serializes the workload; U-235's hosted parallel wall time is not promised. OS browser packages are installed by owner outside CI, with no CI sudo; project-scoped browsers and clean exact-SHA checkouts avoid cross-project state.

The entire original source CI definition remains available by manual dispatch as hosted rollback and deployment, including all commands, fail-closed aggregators, four deployment dependencies, main/event/enable-variable restrictions, stale-main rejection and scoped production secrets. The existing Fly host/deployment chain stays intact. No source push or PR automatically starts the migrated hosted test workload. No production credential or deployment job moves to the PC, and this migration never dispatches a release.

Before merging this migration, require its own complete exact-head controller replay, every shard/capture/browser/mission gate, artifact inventory and genuine App results. Passing source tests never supplies owner play/visual/voice approval. Rollback restores the source pull_request/main-push triggers and requires actual latest-head hosted checks; it never enables a source self-hosted runner or drops coverage.
